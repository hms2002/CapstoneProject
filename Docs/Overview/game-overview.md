# 게임 개요

## 정체성

- 장르: 허브 기반 로그라이트 액션 게임
- 기본 구조: 허브 -> 복도 -> 보스 -> 반복 -> 최종 복도 -> 최종 보스 -> 허브 복귀
- 현재 프로젝트는 전투, 이동, 씬 전환, 대화, 영구 성장 구조를 검증하는 프로토타입 단계다.

## 핵심 런 루프

- 런은 허브의 시작 포탈에서 시작한다.
- 일반 런은 3개의 일반 스테이지와 1개의 최종 스테이지로 구성된다.
- 일반 스테이지는 각각 하나의 세트로 본다.
  - 복도 씬 1개
  - 해당 복도에 대응하는 보스 씬 1개
- 최종 스테이지도 하나의 세트로 본다.
  - 최종 복도 씬 1개
  - 최종 보스 씬 1개
- 최종 보스를 클리어하면 허브로 복귀한다.

## 허브 규칙

- 허브는 전투 상태를 이어받는 씬이 아니다.
- 런이 끝나고 허브로 돌아오면 다음 상태를 초기화해야 한다.
  - 무기 인벤토리 비우기
  - 유물 인벤토리 비우기
  - 일시적 Gameplay Effect 제거
  - 일시적 Gameplay Tag 제거
- 영구 성장 요소는 허브에서도 유지되어야 한다.
- 허브에서 런으로 넘어갈 시 상태는 초기화, 그러나 인벤토리는 유지한다.

## 영구 성장

- 업그레이드 트리 구매 상태는 런이 끝나도 유지된다.
- NPC 호감도와 관련 해금은 유지된다.
- 무기와 유물 해금 상태는 유지된다.
- 숏컷과 맵 영구 진행도는 유지된다.

## 런 중 성장

- 런 중에 획득한 무기와 유물은 해당 런 동안의 임시 성장이다.
- 허브로 돌아오면 런 인벤토리는 유지되지 않는다.
- 런 경로는 고정 시퀀스를 직접 만드는 방식이 아니라, 라우트 풀에서 동적으로 생성하는 방향을 따른다.

## 포탈 규칙

- 포탈은 씬에 미리 배치된다.
- 허브 시작 포탈은 `RunRouteCatalogSO`를 가질 수 있다.
- 허브 시작 포탈은 각자 자기만의 pending run plan을 만들 수 있다.
- 플레이어가 허브 시작 포탈 하나를 고르면 그 포탈의 pending plan이 active plan이 된다.
- 복도 포탈은 현재 스테이지의 보스 씬으로 이동한다.
- 보스 출구 포탈은 다음 복도로 이동하며, 마지막 스테이지에서는 허브 복귀로 해석된다.

## 프로토타입 메모

- 보스 클리어 후 연출은 아직 프로토타입 수준이다.
- 추후 결과창을 띄운 뒤 허브 복귀를 진행하는 구조를 목표로 한다.
- 일부 시스템은 먼저 단순하게 구현한 뒤 책임을 분리할 예정이다.

## 문서 사용 원칙

- 실제 기획 의도가 이 문서보다 우선한다.
- 문서와 실제 설계가 어긋나면, 설계를 확정한 뒤 문서를 갱신한다.
