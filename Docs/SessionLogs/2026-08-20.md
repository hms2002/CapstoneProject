# 2026-08-20 Session Log

## Fire Relics Lean Implementation

### Changed

- Extended attacker-owned `BurnSourceRuntime` with token-scoped stack-damage threshold rules and applied their resolved multiplier in `BurnStatus2D` immediately before HP damage dispatch.
- Added a shared managed Burn relic logic for tick interval, damage coefficient, application amount, first application, critical permission, and target-stack damage scaling.
- Added `SunFragmentOrbitController`: it generates Lean orange squares every two seconds, orbits the player, damages the first contacted enemy for 100% live Fire Damage, applies level-scaled Burn, then destroys that fragment.
- Repurposed the existing `RD_FireBonusRelic` ID and asset as `타오르는 심핵` to preserve save compatibility, with eight levels from +2 to +16 Fire Damage.
- Added definitions and strategies for `녹아내린 종`, `매캐한 향로`, `휴대용 화로`, `태양의 파편`, `작열하는 송`, `불타는 깃털`, and `홍련의 왕`.
- Registered all eight fire relic definitions in both `ItemDatabase.allRelics` and `ItemDatabase.defaultUnlockedRelics` for immediate testing.
- Used the existing fire relic icon as a placeholder for all eight definitions and a runtime square on `Projectile/4` for `태양의 파편`, matching the approved Lean presentation scope.
- Kept the legacy element gauge and its migration backlog unchanged.
