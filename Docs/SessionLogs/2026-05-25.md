## Slime Queen phase 2 drain pull ownership fix

Request:
- Fix P2 Slime Queens stopping as soon as they touch the open drain suction range.
- Match the intended flow: enter suction range, get pulled to the drain, sink for 4 seconds with sinking animation, come back up, restore the drain, then resume patterns.

Cause:
- `BeginDrainControlLock()` set the shared pit-fall runtime lock, and `SlimeQueenBossBase.Update()` used that lock to call `movementMotor.StopAllMotion()` every frame.
- `MovementMotor2D.FixedUpdate()` could also overwrite `DrainPipe`'s direct Rigidbody velocity with zero.

Changes:
- Changed `SlimeQueenPhaseTwoBase.Update()` so drain-locked P2 bosses skip the shared base update while the drain owns the sequence.
- Moved P2 drain context creation to the suction-acquisition step so it can capture and restore the original `MovementMotor2D` enabled state.
- Disabled the P2 boss `MovementMotor2D` during suction/submerged drain ownership, then restored it when the boss leaves the drain.
- Changed P2 drain pulling to use direct `Rigidbody2D.MovePosition` toward the drain center instead of relying on a velocity that the movement motor can overwrite.
- Kept the existing 4-second submerged wait, P2Short `isSinking` animation hook, control restore, and drain reset flow.
- Added a safe P2Long `isSinking` animation hook. The current P2Long Animator Controller does not define that bool, so the hook no-ops until the parameter/transition is authored.
