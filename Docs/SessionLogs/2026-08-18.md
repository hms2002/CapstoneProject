## Unconnected socket collision sealing

### Changed

- Strengthened room authoring validation so every socket cell must contain both Floor and Wall tile data.
- Added runtime invariants that connected socket endpoints lose their Wall tiles while every unconnected endpoint retains its Wall tile.
- Matched the generated Wall Tilemap to the corridor collision setup with the `Ground` layer, a static `Rigidbody2D`, and a merged `CompositeCollider2D`.
- Refactored `DungeonRoomBuilder` to begin with every socket closed by its authored Wall tile and a dedicated invisible one-cell `BoxCollider2D`, then remove both only for endpoints selected by a layout connection.
- Added installer verification for actual collision coverage at each unused socket, not only Wall tile presence.

### Why

- A multi-socket room could connect through one socket while another unused socket remained physically passable. The Wall tile was still present, but its sprite-derived collider shape did not cover the socket cell center, so tile presence alone did not guarantee a sealed exit.

### Verification

- Unity batchmode generated the configured six-room layout and verified all authored socket endpoints began closed, `10` connected endpoints were opened, and the remaining `11` endpoints retained exactly `11` socket blockers.
- The single-socket Boss sweep still completed all `128` Seeds.

- `dotnet build Editor.csproj -m:1 -nr:false` completed with 0 errors and 259 existing warnings.

### Remaining risks

- Interactive Play Mode remains the final smoke test for the real player collider and movement code against the generated blockers.
- The v0 blocker assumes one-cell sockets. Multi-cell socket support must generate blocker geometry from socket width rather than reuse this implementation unchanged.

## Two-cell logical sockets for two-cell doors

### Changed

- Added `width` to `RoomSocketData` and centralized direction-dependent span calculation in `RoomSocketGeometry`.
- Defined `localCell` as the canonical left/bottom start cell: Up/Down spans extend right, while Left/Right spans extend upward.
- Updated the room-piece editor to create, display, move, validate, bake, and reload two-cell logical sockets.
- Updated layout assembly to connect only opposite-facing sockets with equal width and align their span start cells.
- Updated runtime building to require Floor and Wall on both cells, build one `2x1` or `1x2` blocker, remove two Wall cells per connected endpoint, and center one Door over the full socket span.
- Regenerated the Prototype Start/Combat/Boss templates with explicit width `2` socket data and closed Wall/Floor data on both cells.

### Why

- The shared Door prefab is two cells wide. Modeling its halves as separate sockets would allow partial or split connections, while a single logical socket keeps the entire doorway atomic.

- Removed the builder's manual same-room monster registration loop and the dynamic-component workaround in `ChestInteractable`.
