## 모든 무기의 공격 중 이동 — GAS 실행부터 이동 출력까지 구조 수정

### 범위와 확인

- 사용자는 현상이 특정 무기가 아닌 **전부**에서 발생한다고 확인했다. 입력 조건만 바꾸는 대신 GAS 실행·애니메이션·런지·PlayerIntent·MovementMotor 경계를 검토했다.
- 입력의 TryActivate 성공값은 예약 허용 설정에서 버퍼 접수도 뜻한다. 현재 플레이어 프리팹의 enableExclusiveActivationBuffer는 0이므로 예약은 잠재 결함 경로이며 현재 증상의 확정 원인이라고 보지 않는다.
- 기존 입력 잠금은 실제 logic 대기/RecoveryOverride보다 이른 시점에 기본 recoveryTime으로 타이머를 계산했고, 모션 80%에서 해제했다. 실제 animation playback과 관찰의 Animator fallback도 달랐다. 실행 후 GetBasicAttack을 다시 비교하는 방식은 선택이 바뀌는 공격에 취약했다.
- MovementMotor는 PlayerIntent의 걷기와 AbilityMotion의 런지를 이미 분리한다. 모터·벽 미끄러짐·런지 방향·콤보 만료 코드를 추가 변경하지 않았다.

### 변경 파일과 이유

- [AbilitySystem.cs](../../Assets/_Project/Runtime/Core/Abilities/AbilitySystem.cs): 실제 실행 시작/종료 이벤트와 playback과 동일한 Animator 조회를 제공한다. 새 serialized field 없음.
- [AbilityExecutionCoordinator.cs](../../Assets/_Project/Runtime/Core/Abilities/AbilityExecutionCoordinator.cs): 실행 token을 만든 뒤 logic 전에 시작 통지, 종료 시 예약된 다음 실행을 소비하기 전에 종료 통지를 보낸다. 동일 spec 재실행 순서를 보존한다.
- [AbilityPresentationRouter.cs](../../Assets/_Project/Runtime/Core/Presentation/AbilityPresentationRouter.cs): 기존 Animator 선택 함수를 공유하여 조회와 실제 재생의 fallback을 일치시킨다.
- [PlayerCombatInput2D.cs](../../Assets/_Project/Runtime/Features/Player/Input/PlayerCombatInput2D.cs): enable/disable 동안 실행 이벤트 구독, 실행된 평타 spec/token/Animator를 기록한다. 요청 성공이나 재입력은 잠금을 시작하지 않는다. 실제 실행/후딜·관찰된 모션(1.0 또는 상태 이탈)·런지가 끝나야 해제한다. 취소 token/종료 및 기존 UI·교체·비활성화 정리를 유지한다. 추정 후딜 타이머와 요청 측 BeginMeleeControlLock을 제거했다.
- [PlayerControlAndChestRegressionPlayModeTests.cs](../../Assets/_Project/Tests/PlayMode/Procedural/PlayerControlAndChestRegressionPlayModeTests.cs): 실제 AbilitySystem을 사용하는 긴 실행/취소, 예약 접수와 실제 시작의 차이, 완료 경로 테스트를 추가했다. 포션 테스트는 유지한다.
- [AttackLifecycleNativeRegression.cs](../../Tools/Validation/AttackLifecycleNativeRegression.cs): 별도 Unity 프로젝트에서 최신 Core/Gameplay DLL을 실제 Play Mode로 실행하는 재현 검증을 추가했다.
