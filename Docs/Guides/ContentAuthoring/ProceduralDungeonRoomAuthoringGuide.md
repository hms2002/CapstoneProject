# 절차적 던전 방 제작 툴 사용 가이드

## 이 문서의 목적

이 문서는 기획자와 레벨 디자이너가 `Room Piece Editor`로 다음 작업을 안전하게 수행하는 방법을 설명합니다.

- 테마 라이브러리를 선택하고 기존 방을 찾는다.
- 기본 바닥·벽과 고정 장식 레이어를 가진 새 방부터 몬스터·상자·포털이 있는 방까지 제작한다.
- 기존 `RoomTemplateSO`를 불러와 수정하거나 복제한다.
- 저장하지 않은 현재 방을 실제 배치 알고리즘에 넣어 동적 맵을 미리 본다.
- 검증을 통과한 방만 저장하고 테마 라이브러리에 등록한다.

기술 구조와 런타임 책임이 필요하면 [Procedural Dungeon Room Pipeline](../../StructureMemory/ProceduralDungeonRoomPipeline.md)을 함께 읽습니다.

Notion 가져오기용 하위 페이지 묶음은 `Docs/NotionImport/ProceduralDungeonRoomAuthoring_NotionImport.zip`에 있습니다.

## 가장 빠른 시작

1. Unity 메뉴에서 `Tools > Dungeon > Room Piece Editor`를 엽니다.
2. 창 상단의 `테마 룸 라이브러리`를 선택합니다.
3. `새 방 만들기`에서 방 ID, 역할, 예약 크기를 입력합니다.
4. `전용 작업 공간에서 새 방 만들기`를 누릅니다.
5. `2. 타일`에서 Floor와 Wall을 그리고 필요한 장식 레이어를 추가합니다.
6. `3. 출입구`에서 최소 한 개의 2칸 소켓을 배치합니다.
7. 필요하면 `4. 오브젝트`에서 몬스터, 상자, 포털, 프롭을 배치합니다.
8. `6. 맵 미리보기`에서 실제 조립 결과를 확인하고, 생성 수치를 바꿨다면 `현재 미리보기 설정을 테마에 적용`합니다.
9. `5. 검증·저장`에서 검증을 통과시킨 뒤 저장합니다.

처음 사용할 때는 기존 방 하나를 `복제해서 새 방 만들기`로 열어 각 단계의 완성 상태를 살펴보는 방법이 가장 쉽습니다.

## 툴이 보호하는 것

방 제작은 저장되지 않는 전용 additive 작업 공간에서 이루어집니다. 현재 열려 있는 게임 씬의 Hierarchy에 방 제작 오브젝트를 추가하지 않습니다.

- 작업 공간을 열거나 닫아도 기존 게임 씬을 자동 저장하거나 교체하지 않습니다.
- 저장하지 않은 변경이 있는 `Untitled` 씬이 열려 있으면 작업 공간 생성을 막습니다.
- 맵 미리보기 생성 자체는 원본 `RoomTemplateSO`, `RoomThemeLibrarySO`, 생성 프로필을 변경하지 않습니다. `현재 미리보기 설정을 테마에 적용`을 명시적으로 눌렀을 때만 선택 테마의 `DungeonGenerationProfileSO`가 갱신됩니다.
- 맵 미리보기를 생성하거나 지우는 작업은 현재 방의 저장 필요 상태에 포함되지 않습니다.
- 방을 바꾸거나 작업 공간을 닫을 때 저장하지 않은 편집 내용이 있으면 확인 창이 나타납니다.

전용 작업 공간 자체를 씬 에셋으로 저장하지 마세요. 저장 결과물은 `RoomTemplateSO`입니다.

## 핵심 용어

| 용어 | 의미 |
| --- | --- |
| 테마 룸 라이브러리 | 한 보스/던전 테마에서 배치 후보로 사용할 방 목록입니다. |
| 방 템플릿 | 방 하나의 레이아웃, 타일, 소켓, 오브젝트 배치를 저장한 `RoomTemplateSO`입니다. |
| 예약 크기 | 배치 충돌 검사에 사용하는 직사각형 영역입니다. |
| 실제 방 모양 | Floor 타일이 칠해진 모양입니다. ㄴ자·ㄱ자 방도 예약 영역은 바깥쪽 직사각형을 사용합니다. |
| 고정 타일 레이어 | `UnderFloor`, `Floor`, `FloorDetail`, `GroundDecoration`, `Wall`, `WallDetail`, `Foreground`, `OverlayFX` 여덟 슬롯입니다. |
| 소켓 | 다른 방과 연결될 수 있는 경계의 2칸 출입구 후보입니다. |
| Placement Id | 한 방 안에서 오브젝트를 식별하는 고유 문자열입니다. |
| Travel Slot Id | 방의 이동 지점을 식별하는 고유 문자열입니다. 목적 씬 연결은 복도 씬에서 별도로 지정합니다. |
| 등장 가중치 | 같은 역할의 후보 중 해당 방이 선택될 상대 확률입니다. |
| Seed | 같은 라이브러리와 생성 설정에서 같은 배치 결과를 재현하는 정수입니다. |

## 작업 시작 방법

### 새 방 만들기

`새 방 만들기`에서 다음 값을 입력한 뒤 `전용 작업 공간에서 새 방 만들기`를 누릅니다.

| 입력 | 작성 기준 |
| --- | --- |
| 방 ID | 선택한 라이브러리 안에서 고유하게 작성합니다. 예: `Dragon_Combat_Wide_02`. |
| 방 역할 | 아래 역할 표를 참고합니다. |
| 예약 크기 | 방의 가장 바깥쪽 타일까지 포함하는 가로·세로 셀 수입니다. |
| 난이도 단계 | 향후 난이도 정책에 사용할 메타데이터입니다. 현재 배치기는 이 값으로 방을 걸러내지 않습니다. |
| 등장 가중치 | `0`보다 커야 배치 후보가 됩니다. 값이 클수록 같은 역할 후보 중 더 자주 선택됩니다. |

### 기존 방 수정하기

다음 방법 중 하나로 방을 선택합니다.

- `라이브러리 방 목록`에서 방 카드의 `편집`을 누릅니다.
- Project 창에서 `RoomTemplateSO`를 선택한 뒤 `기존 방 직접 선택 > 원본 편집`을 누릅니다.

불러온 방은 작업 공간의 편집 복사본입니다. `검증 후 원본 템플릿 갱신`을 누르기 전에는 원본 에셋이 변경되지 않습니다.

### 기존 방을 복제하기

라이브러리 방 카드의 `복제` 또는 `복제해서 새 방 만들기`를 누릅니다.

- 방 ID 뒤에 `_Copy`가 붙습니다.
- 원본 템플릿 연결은 제거됩니다.
- 저장할 때 새 에셋 경로를 선택합니다.
- 저장 전 방 ID가 라이브러리의 다른 방과 겹치지 않는지 확인합니다.

## 방 역할 선택

| 역할 | 현재 생성기에서의 의미 |
| --- | --- |
| `Start` | 첫 방 후보입니다. 라이브러리에 사용 가능한 Start 방이 최소 한 개 필요합니다. |
| `Combat` | 일반 확장 방 후보입니다. |
| `Treasure` | 보상용 확장 방 후보입니다. |
| `Shop` | 상점용 확장 방 후보입니다. |
| `Event` | 이벤트용 확장 방 후보입니다. |
| `Boss` | `보스 방 포함`이 켜졌을 때 마지막 방 후보입니다. |
| `Exit` | 현재 v0 배치기의 일반 확장 후보에는 포함되지 않습니다. |

`Start`나 `Boss` 방을 하나의 소켓만 가진 종단형으로 만들 수 있습니다. 단, 중간 확장 방의 소켓을 너무 적게 만들면 다음 방을 붙일 열린 소켓이 사라질 수 있습니다.

## 1. 기본

`1. 기본`에서는 방의 배치용 메타데이터를 관리합니다.

- `방 ID`는 라이브러리 안에서 고유해야 합니다.
- `예약 크기`는 충돌 검사 영역입니다. Floor가 없는 빈 구역도 예약 영역에 포함됩니다.
- 큰 ㄴ자·ㄱ자 방은 가장 튀어나온 부분을 모두 포함하는 직사각형 크기를 입력합니다.
- `등장 가중치`가 `0`이면 미리보기와 런타임 배치 후보에서 제외됩니다.
- 상단 라이브러리를 바꾸면 방 검색, 추천 프리팹, 저장 후 자동 등록 대상도 함께 바뀝니다.

예약 크기를 줄일 때는 기존 Floor, Wall, 소켓, 오브젝트가 새 영역 밖으로 나가지 않는지 확인하세요.

## 2. 타일

이 툴은 별도의 타일 브러시를 제공하지 않고 Unity의 Tile Palette를 그대로 사용합니다.

각 버튼은 해당 레이어를 선택하고 괄호 안에 예약 영역 내부 타일 수를 표시합니다.

| 레이어 | 용도 | 통과·충돌 규칙 |
| --- | --- | --- |
| `UnderFloor` | 물, 하수, 용암, 낭떠러지처럼 바닥 아래에 보이는 배경 | 통과 가능. 물리 판정에 참여하지 않습니다. |
| `Floor` | 플레이어와 오브젝트가 이동하는 기본 바닥 | 통과 가능하며 Ground 물리 스캔 기준입니다. |
| `FloorDetail` | 균열, 얼룩, 이끼, 카펫 같은 평면 장식 | `Floor` 위에만 배치하며 통과 가능합니다. |
| `GroundDecoration` | 풀, 종이, 작은 잔해, 얕은 술병 같은 입체감 있는 장식 | `Floor` 위에만 배치하며 통과 가능합니다. |
| `Wall` | 방 외곽, 절벽, 막힌 공간 | 통과 불가. 이 레이어만 Tilemap Collider를 가집니다. |
| `WallDetail` | 벽기둥, 깃발, 부조, 배관 같은 벽 부착 장식 | `Wall` 위에만 배치합니다. 별도 Collider 없이 아래 Wall 충돌을 따릅니다. |
| `Foreground` | 아치 상단, 기둥 윗부분, 천장처럼 캐릭터 앞에 보여야 하는 장식 | 통과 가능하며 `ForeGround` 정렬 레이어로 출력됩니다. |
| `OverlayFX` | 안개, 빛줄기, 먼지, 어둠, 반사광 같은 방 오버레이 | 통과 가능하며 `ForeGround` 정렬 레이어로 출력됩니다. |

`GroundProp`은 Tilemap 슬롯이 아닙니다. 상자, 큰 바위, 책상처럼 개별 충돌과 동작이 필요한 물체는 `4. 오브젝트`에서 `Prop`으로 배치하고, 충돌 여부와 물리 레이어는 프리팹에서 설정합니다.

### 바닥 그리기

1. `Floor` 버튼을 누릅니다.
2. Unity Tile Palette에서 테마에 맞는 Floor 타일을 선택합니다.
3. Scene View에서 실제로 걸을 수 있는 모든 셀을 칠합니다.

Floor 타일이 실제 방 모양을 결정합니다. ㄴ자 방의 비어 있는 안쪽 모서리에는 Floor를 칠하지 않습니다.

### 벽 그리기

1. `Wall` 버튼을 누릅니다.
2. Unity Tile Palette에서 테마에 맞는 Wall 타일을 선택합니다.
3. 방의 외곽과 내부 장애물을 칠합니다.

### 반드시 지켜야 하는 소켓 타일 규칙

소켓으로 사용할 경계 2칸에는 Floor와 Wall을 모두 칠합니다.

- Floor는 연결된 뒤 플레이어가 통과할 길입니다.
- Wall은 해당 소켓이 선택되지 않았을 때 출구를 막습니다.
- 실제 맵 생성 시 연결된 소켓의 Wall만 빌더가 제거합니다.
- 연결되지 않은 소켓은 계속 막힌 상태로 남습니다.

방 샘플 단계에서 출입구를 미리 뚫어 두면 안 됩니다.

### 타일 수 표시

툴은 예약 영역 내부의 여덟 타일 레이어별 타일 수를 보여줍니다. 예약 영역 밖에 그린 타일은 경고로 표시되며 저장 데이터에서 제외됩니다.

## 3. 출입구

현재 소켓 폭은 문과 복도 폭에 맞춰 항상 2칸입니다.

### 가장 쉬운 배치 방법

1. `Scene View에서 경계를 클릭해 소켓 배치`를 켭니다.
2. Scene View에서 방의 원하는 경계를 클릭합니다.
3. 초록색 미리보기 선과 바깥 방향을 확인합니다.
4. 배치 모드는 `Esc`로 종료합니다.

툴이 다음 항목을 자동 처리합니다.

- 가장 가까운 방 경계 선택
- 방 바깥쪽 Direction 선택
- 2칸 시작 위치 보정
- 기존 소켓과 겹치지 않는 가까운 위치 탐색

### 빠른 중앙 배치

`위`, `오른쪽`, `아래`, `왼쪽` 버튼은 해당 경계 중앙 근처의 빈 2칸에 소켓을 추가합니다.

### 소켓 카드

| 입력 | 의미 |
| --- | --- |
| Socket Id | 방 안에서 소켓을 구분하는 고유 이름입니다. |
| Direction | 방 바깥쪽을 향하는 방향입니다. |
| Width | 현재 고정값 `2 cells`입니다. |
| Local Cell | 2칸 소켓의 기준 시작 셀입니다. |

Up/Down 소켓은 Local Cell에서 오른쪽으로 2칸, Left/Right 소켓은 위쪽으로 2칸을 차지합니다. 일반 작업에서는 좌표를 직접 계산하기보다 클릭 배치를 권장합니다.

소켓을 선택하면 Scene View 이동 핸들로 위치를 조정할 수 있습니다. 이동 후 반드시 경계 안의 2칸인지, 다른 소켓과 겹치지 않는지, 두 셀 모두 Floor와 Wall을 가지는지 검증합니다.

## 4. 오브젝트

오브젝트는 Floor 셀을 기준으로 배치됩니다.

### 배치 순서

1. `종류`를 선택합니다.
2. `추천 프리팹`에서 선택하거나 `배치할 프리팹`에 직접 지정합니다.
3. `방 중앙에 배치 후 Scene View에서 이동`을 누릅니다.
4. 생성된 오브젝트를 Scene View에서 이동·회전·크기 조절합니다.
5. 카드의 Placement Id가 방 안에서 고유한지 확인합니다.

추천 프리팹은 선택한 라이브러리의 기존 방 데이터에서 같은 종류만 모아 보여줍니다. 프로젝트 폴더를 하드코딩해서 검색하지 않습니다.

### 종류별 프리팹 조건

| 종류 | 프리팹에 필요한 구성 |
| --- | --- |
| `Monster` | 자식 포함 `Enemy` 컴포넌트가 필요합니다. 실제 적이 아니라 방 입장 시 사용할 스폰 위치이며, 배치 프리팹은 프로필이 없거나 실패했을 때의 fallback입니다. |
| `Chest` | 자식 포함 `TreasureChest` 컴포넌트가 필요합니다. |
| `Portal` | 자식 포함 `ScenePortal` 컴포넌트가 필요합니다. |
| `Prop` | 별도 필수 컴포넌트는 없습니다. 동작에 필요한 설정은 완성된 프리팹이 소유해야 합니다. |

오브젝트의 기준 셀은 예약 영역 안에 있어야 하고 그 셀에 Floor가 있어야 합니다. 큰 프리팹의 전체 스프라이트나 Collider가 벽 밖으로 나가는지는 자동 검증하지 않으므로 Scene View에서 직접 확인합니다.

함정, 레버, 퍼즐과 런타임 위치 앵커는 현재 별도 오브젝트 Kind가 아닙니다. 자체 완결형 `Prop` 프리팹 안에 필요한 컴포넌트와 `ProceduralRoomAnchor`를 함께 두고 배치합니다. 앵커는 독립적인 방 데이터 목록으로 저장되지 않으며, 임의 컴포넌트의 단계·작동 여부 같은 내부 상태도 자동 보존되지 않습니다. 런 중 보존이 필요하면 해당 프리팹이 안정적인 ID와 상태 캡처·복원 계약을 별도로 제공해야 합니다.

전투 방은 `방 기본 정보 > 몬스터 스폰 프로필`을 지정합니다. 이 프로필이 `CommonMelee/Ranged/Tank StageMonsterSet`을 사용하면 첫 번째·두 번째·세 번째 일반 보스 진행도에 따라 실제 몬스터 프리팹이 바뀝니다. 몬스터는 맵 생성 시 미리 나타나지 않고 플레이어 몸체가 방 안쪽 입장 Trigger에 완전히 들어온 뒤 생성됩니다.

### Monster Kill Lock 상자 연결

1. `ChestMonsterKillLock`이 이미 구성된 상자 프리팹을 Chest로 배치합니다.
2. 상자의 Placement Id를 고유하게 설정합니다.
3. 각 Monster 카드의 `Kill Lock Chest`에서 해당 상자를 선택합니다.
4. 상자 카드의 `Linked Monsters` 수를 확인합니다.

Kill Lock 동작과 연출은 상자 프리팹이 소유합니다. 툴이나 던전 빌더가 일반 상자에 Kill Lock 컴포넌트나 연출을 임의로 추가하지 않습니다.

### 씬 이동 Endpoint 슬롯

일반 `Portal` 오브젝트와 별도로, 새 데이터 기반 씬 연결에 사용할 이동 슬롯을 같은 단계에서 배치할 수 있습니다.

1. `매개체 방식`을 선택합니다.
2. `Trigger` 방식이면 `Trigger Size (월드 단위)`에 실제 진입 판정의 가로·세로 크기를 입력합니다. 이 값은 매개체 Transform Scale과 독립적입니다.
3. 외형·애니메이션·Collider가 준비된 매개체 프리팹이 있으면 `매개체 프리팹`에 지정합니다. 비워 두어도 입력한 크기의 BoxCollider2D가 런타임에 만들어집니다.
4. `이동 슬롯을 방 중앙에 추가`를 누릅니다.
5. Scene View에서 매개체의 출발 위치를 옮기고 회전·외형 크기를 조절합니다. 선택한 Trigger 슬롯의 파란 사각형은 실제 판정 크기를 표시합니다.
6. 카드의 `Slot Id`가 같은 방 안에서 고유한지 확인합니다. 배치 후에도 카드의 `Trigger Size`를 수정할 수 있습니다.
7. 이동 후 플레이어를 매개체와 다른 위치에 세우려면 `도착 위치 별도 지정`을 켭니다.
8. 카드의 `Select`를 누른 뒤 Scene View의 녹색 도착 핸들을 안전한 Floor 셀로 옮깁니다. 숫자 입력이 편하면 `도착 Local Cell`과 `도착 Cell Offset`을 직접 수정할 수도 있습니다.

| 방식 | 사용 시점 |
| --- | --- |
| `Interaction` | 문, 포털처럼 플레이어가 상호작용 키를 눌러 이동합니다. |
| `Trigger` | 경계 통과처럼 2D Trigger 진입 즉시 이동합니다. |
| `ArrivalOnly` | 해당 방향에서는 출발할 수 없고 다른 씬에서 도착 위치로만 사용합니다. |

방 템플릿은 목적 씬이나 보스 테마를 저장하지 않습니다. 방을 저장한 뒤 같은 패널의 `이동 연결·연출 편집기 열기` 또는 `Tools > Dungeon > Procedural Travel Binding Editor`를 사용합니다.

`도착 위치 별도 지정`을 끄면 기존과 같이 매개체 Transform 또는 매개체 프리팹의 기존 Arrival Anchor를 사용합니다. 켜면 방 데이터의 녹색 도착점을 최우선으로 사용하므로, 로비에서 복도로 들어왔을 때 플레이어를 문턱 안쪽에 배치하면서 같은 매개체로 복귀 이동을 유지할 수 있습니다. 도착점은 방 bounds 안의 Floor 셀이어야 하며 저장 검증과 런타임 빌더가 모두 확인합니다.

1. 이동 Endpoint가 들어갈 절차 복도 씬을 열고 대상 `DungeonRoomBuilder`를 선택하거나 `현재 씬에서 찾기`를 누릅니다.
2. 저장한 방과 Slot Id를 선택합니다.
3. `SceneConnectionSO`와 이 방이 담당하는 Connection Side A/B를 선택합니다.
4. 현재 Side의 출발 방향 사용 여부와 실제 이동 방향의 런 동작·전환 연출 프로필을 확인합니다. `ArrivalOnly`는 반대 Side에서 현재 Side로 들어오는 방향의 연출을 편집합니다.
5. `현재 씬 Builder에 바인딩 추가/갱신`을 누른 뒤 게임플레이 씬을 직접 저장합니다.

편집기는 다음 네 값을 `DungeonRoomBuilder > Travel Endpoints > Travel Endpoint Bindings`에 기록합니다.

- Room Id
- Slot Id
- SceneConnectionSO
- 해당 방이 담당하는 Connection Side A/B

이 분리 덕분에 같은 방을 여러 테마 씬에서 재사용할 수 있습니다. 바인딩이 없는 슬롯은 런타임에서 비활성 상태로 남으며, 연결 에셋의 해당 A/B endpoint 씬 이름이 현재 씬과 다르면 편집기에서 경고하고 런타임 생성도 실패합니다. `ArrivalOnly`는 연결 데이터의 역방향도 꺼서 데이터와 매개체 양쪽에서 단방향을 보장합니다. 편집기는 씬을 자동 저장하지 않습니다.

### 테마 복도 표준 슬롯

현재 세 일반 보스 절차 복도(Shadow, Dragon, Slime)는 다음 규칙으로 설치됩니다. 최종 DemonKing은 절차 복도 슬롯 대상이 아니며, HUB의 기존 상호작용 포탈이 전용 카탈로그를 통해 고정 휴식 씬 `DemonkingCorridor`로 이동합니다.

| 방 | Slot Id | 방식 | 역할 |
| --- | --- | --- | --- |
| 각 테마 Start | `LobbyGate` | `Trigger` | 로비에서 도착하고, 다시 경계를 통과하면 로비로 돌아갑니다. 도착 직후에는 trigger 역이동이 잠시 억제되고, 비활성 구간에는 도착 Anchor 반대편 경계가 물리 콜라이더로 막힙니다. |
| 각 테마 Boss | `BossGate` | `Interaction` | 공통 데이터 기반 포털로 해당 테마 보스 씬에 진입합니다. |

복도 기본 콘텐츠를 다시 만들었다면 `Tools > Dungeon > Install Procedural Corridor Travel Configuration`으로 HUB·보스 이동 연결만 재설치할 수 있습니다. 복도 간 토관 이동은 현재 봉인되어 다시 등록되지 않으며, 이 명령은 `ProtoTypeHub`의 배치 위치를 수정하지 않습니다.

로비 쪽은 단순 Collider만 배치해서는 안 됩니다. 완성형 로비 게이트에는 `SceneTravelEndpoint`, `SceneTravelTrigger2D`, 해당 테마의 `Lobby_*_Corridor` 연결 에셋, 도착 Anchor, 특정 테마 route context 설정이 함께 필요합니다.

## 5. 검증·저장

### 저장 전 검증

`지금 전체 검증`을 눌러 오류 목록을 확인합니다. 창 아래쪽의 자동 검증 요약도 현재 상태를 주기적으로 갱신합니다.

주요 검증 항목은 다음과 같습니다.

- Room Id가 비어 있지 않고 선택한 라이브러리 안에서 고유한가.
- Grid와 여덟 고정 Tilemap 슬롯 참조가 모두 존재하는가.
- 예약 크기가 유효하고 영역 안에 타일이 존재하는가.
- FloorDetail·GroundDecoration은 Floor 위에, WallDetail은 Wall 위에 있는가.
- 소켓이 최소 한 개이고 ID, 방향, 위치, 폭이 올바른가.
- 각 소켓의 두 셀에 Floor와 Wall이 모두 있는가.
- 오브젝트 Placement Id가 고유하고 프리팹 종류가 맞는가.
- 오브젝트 기준 셀이 예약 영역 안이며 Floor 위에 있는가.
- Monster의 Kill Lock 상자 연결이 실제 상자 Placement Id로 해석되는가.
- Travel Slot Id가 방 안에서 고유하고 Floor 셀 위에 있는가.

### 새 방 저장

1. 필요하면 `저장 후 선택한 테마 라이브러리에 자동 등록`을 켭니다.
2. `검증 후 새 RoomTemplateSO로 저장`을 누릅니다.
3. Unity 저장 창에서 기존 테마 방들과 일관된 폴더와 에셋 이름을 선택합니다.

기존 에셋이 있는 경로는 덮어쓰지 않습니다.

### 불러온 원본 갱신

1. `갱신할 원본`이 의도한 `RoomTemplateSO`인지 확인합니다.
2. `검증 후 원본 템플릿 갱신`을 누릅니다.
3. 확인 창에 표시된 에셋 경로를 다시 확인한 뒤 적용합니다.

원본을 바꾸지 않고 변형 방을 만들려면 원본 갱신 대신 복제 또는 새 방 저장을 사용합니다.

## 6. 맵 미리보기

맵 미리보기는 런타임과 같은 배치기와 여덟 고정 Tilemap 슬롯을 사용합니다. 레이아웃 정책을 비우면 기존 `DungeonLayoutAssembler`, 정책을 지정하고 보스 방을 포함하면 `DungeonGraphLayoutAssembler`가 실행됩니다. 가짜 배치 그림이 아니라 같은 라이브러리·Seed·정책·설정에서 런타임과 같은 방 선택, 연결 및 타일 결과를 계산합니다.

### 기본 사용 순서

1. 상단의 테마 룸 라이브러리를 확인합니다.
2. `테마 생성 프로필`이 자동으로 선택되는지 확인합니다. 없다면 `테마 프로필 찾기/만들기`를 누릅니다.
3. 편집 중인 내용을 함께 시험하려면 `저장하지 않은 현재 편집 방 포함`을 켭니다.
4. 필요하면 `레이아웃 정책`을 선택합니다. 정책을 사용할 때는 보스 방 포함을 켭니다.
5. Seed, 방 개수, 보스 방 포함 여부와 고급 복도 설정을 조절합니다.
6. 필요하면 복도 타일 오버라이드를 지정합니다.
7. `동적 생성 미리보기`를 눌러 Scene View 결과와 상태 메시지를 확인합니다.
8. 결과를 실제 테마 기본값으로 채택하려면 `현재 미리보기 설정을 테마에 적용`을 누릅니다.

### 미리보기 입력

| 입력 | 의미 |
| --- | --- |
| 생성 프로필 | 선택 테마의 실제 런타임 생성 설정 에셋입니다. `프로필 값 불러오기`로 저장값을 입력란에 복원합니다. |
| 저장하지 않은 현재 편집 방 포함 | 원본 편집 중이면 라이브러리의 저장본을 현재 복사본으로 임시 대체합니다. 새 방이면 임시 후보로 추가합니다. |
| 레이아웃 정책 | Start→Boss 거리, 분기·순환 수, 역할별 최소 방 수를 적용합니다. 비우면 기존 순차 배치 방식을 사용합니다. |
| 시드 | 같은 조건의 배치를 재현합니다. |
| 보스 방 포함 | 마지막 방을 Boss 후보에서 선택합니다. 사용 가능한 Boss 방이 필요합니다. |
| 방 개수 | Start와 선택적 Boss를 포함한 목표 개수입니다. |
| 바닥/벽 타일 오버라이드 | 복도에 사용할 타일입니다. 비워 두면 라이브러리에서 가장 많이 쓰인 Floor/Wall 타일을 자동 선택합니다. |
| 방당 최대 배치 시도 | 겹치지 않는 다음 방을 찾기 위해 시도할 횟수입니다. |
| 최소 복도 길이 | 모든 연결에 보장할 최소 길이입니다. |
| 방 크기 반영 비율 | 연결되는 두 방의 진행축 크기를 복도 길이에 얼마나 반영할지 정합니다. |
| 복도 길이 난수 폭 | Seed 기반 추가 길이의 최대 범위입니다. |

### 실제 테마에 적용

`현재 미리보기 설정을 테마에 적용`은 Seed, 방 개수, 보스 방 포함, 방당 최대 배치 시도, 레이아웃 정책과 세 복도 길이 값을 선택 테마의 생성 프로필에 저장합니다. 복도 타일 오버라이드는 시각 확인용이므로 프로필에 저장하지 않습니다. 실제 타일 팔레트는 각 테마 씬의 `DungeonRoomBuilder`가 소유합니다.

Shadow, Dragon, Slime 절차 복도 씬은 각자의 프로필을 직접 참조합니다. 안내문에 `활성 Build Settings 씬 1곳에서 사용`이 표시되면 적용 직후부터 다음 씬 생성이 새 설정을 사용합니다. 실행 중 이미 만들어진 맵은 자동 재생성하지 않습니다.

전체 보스 테마 설치기를 다시 실행해도 기존 프로필과 레이아웃 정책 값은 보존됩니다. 프로필이 없는 새 테마에서만 설치 기본값을 만듭니다.

### 반드시 포함할 방

`테마 생성 프로필 > 반드시 포함할 방`에는 NPC, 숏컷, 퀘스트처럼 해당 테마 맵에 정확히 한 번 필요한 확장 방을 등록합니다.

- 먼저 방을 현재 테마 룸 라이브러리에 저장·등록합니다.
- `Start`, `Boss`, `Exit`은 생성기가 별도로 관리하므로 이 목록에 넣지 않습니다.
- 등록한 방은 그래프에서 호환되는 노드를 선점하며 일반 랜덤 후보에서는 제외됩니다.
- 같은 역할의 정책 수보다 보장 방 수가 많으면 보장 방 수가 최소 필요량이 됩니다.
- 빈 참조, 다른 테마 방, 중복 참조, 소켓이 맞지 않는 방은 생성 실패 사유로 표시됩니다.

현재 Slime 공사 NPC와 순간이동 NPC 방은 기획 보류 상태입니다. 방·프리팹 에셋은 보존하지만 룸 라이브러리와 `반드시 포함할 방` 목록에서 제거되어 런타임 맵에는 배치되지 않습니다. 복도 간 토관 출발·도착 방도 같은 방식으로 봉인되어 있습니다.

### Scene View 표식

| 표식 | 의미 |
| --- | --- |
| 초록 방 테두리 | 현재 편집 중인 임시 방이 실제 배치에 선택되었습니다. |
| 다른 색 방 테두리 | 방 역할별 예약 영역입니다. |
| 청록 점선과 점 | 연결된 두 소켓과 연결 방향입니다. |
| `M` | Monster 배치입니다. |
| `C` | Chest 배치입니다. |
| `P` | Portal 배치입니다. |
| `O` | Prop 배치입니다. |
| `EI` | Interaction 이동 Endpoint 슬롯입니다. |
| `ET` | Trigger 이동 Endpoint 슬롯입니다. |
| `EA` | ArrivalOnly 이동 Endpoint 슬롯입니다. |

미리보기는 방 타일과 복도를 실제로 그리지만 Door, Monster, Chest, Portal, Prop 프리팹과 인카운터 로직은 실행하지 않습니다. `EI/ET/EA`도 데이터상의 위치와 방식만 표시하며 씬 이동을 실행하지 않습니다. 상호작용, Kill Lock, 문 닫힘, 몬스터 스폰과 이동 연출은 전용 테스트 씬의 Play Mode에서 확인합니다.

### 현재 방이 0회 등장하는 경우

`저장하지 않은 현재 편집 방 포함`은 현재 방을 후보에 넣는 기능이지 강제로 배치하는 기능이 아닙니다.

- 상태 메시지가 `현재 방 0회`라면 먼저 `랜덤 시드`를 사용해 다른 결과를 확인합니다.
- Room 역할이 현재 생성 단계에서 필요한 역할인지 확인합니다.
- 등장 가중치가 `0`보다 큰지 확인합니다.
- 현재 방을 억지로 보여주기 위해 미리보기에서만 가중치를 과장하지 않습니다. 미리보기와 런타임 선택 규칙이 달라지기 때문입니다.

### 부분 생성 결과

배치 중 열린 소켓이 없어지거나 겹침을 피하지 못하면 배치된 방까지만 표시될 수 있습니다. 상태 메시지의 중단 사유를 확인합니다.

- `No open room socket remains`: 중간 방의 남는 소켓 수를 늘립니다.
- `Failed to place room ... without overlap`: Seed, 배치 시도 수, 복도 길이, 방 크기 또는 소켓 구성을 점검합니다.
- `no usable Start room`: Start 방의 가중치, 크기와 소켓을 점검합니다.
- `no usable Boss room`: 보스 방 포함을 끄거나 유효한 Boss 방을 추가합니다.
- 역할별 할당 실패: 정책의 Treasure/Event/Shop 수보다 해당 타입의 유효한 템플릿이 적은지 확인합니다. 현재 테마 샘플은 Event와 Shop을 제공하지 않으므로 두 할당량을 `0`으로 둡니다.
- 그래프 토폴로지 실패: 방 개수가 최소 보스 거리·분기·순환 목표를 함께 만족할 만큼 충분한지, 선택된 방들의 방향별 소켓이 충분한지 확인합니다.

## 권장 작업 흐름

### 새 전투 방 한 개 추가

1. 같은 테마의 비슷한 크기 Combat 방을 복제합니다.
2. 새 Room Id와 예약 크기를 설정합니다.
3. Floor/Wall 모양을 수정합니다.
4. 소켓을 최소 두 방향에 배치합니다.
5. 테마 라이브러리 추천에서 Monster와 Kill Lock Chest 프리팹을 배치합니다.
6. Monster와 상자를 연결합니다.
7. 현재 방 포함 미리보기를 여러 Seed로 생성합니다.
8. 검증 후 새 템플릿으로 저장하고 라이브러리에 등록합니다.
9. 전용 절차 복도 씬의 Play Mode에서 전투 방 진입과 문 잠금을 확인합니다.

### 큰 ㄴ자·ㄱ자 방 추가

1. 가장 바깥쪽 크기로 예약 직사각형을 정합니다.
2. 실제 다리 부분에만 Floor를 칠합니다.
3. Floor 외곽에 Wall을 구성합니다.
4. 플레이어가 실제로 도달할 수 있는 외곽 경계에만 소켓을 둡니다.
5. 오브젝트가 빈 안쪽 모서리나 좁은 목 부분을 막지 않는지 확인합니다.
6. 긴 복도 설정과 여러 Seed에서 다른 큰 방/복도와 예약 영역이 충돌하지 않는지 확인합니다.

### 종단형 방 추가

Start나 Boss처럼 한 개 소켓만 필요한 방은 소켓이 실제 연결에 소비되는지 확인합니다. 일반 확장 후보를 한 개 소켓으로 만들면 그 방 이후 경로가 끝나므로 라이브러리 전체의 열린 소켓 수를 함께 검토합니다.

## 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| 작업 공간이 열리지 않는다 | 저장하지 않은 변경이 있는 Untitled 씬을 먼저 저장하거나 닫습니다. |
| 방이 미리보기 후보가 되지 않는다 | 가중치가 양수인지, 예약 크기가 유효한지, 올바른 2칸 소켓이 최소 한 개 있는지 확인합니다. |
| 소켓 검증이 실패한다 | 두 셀이 방 경계 안에 있고 Direction이 바깥쪽인지, Floor와 Wall이 모두 있는지 확인합니다. |
| 사용하지 않은 출구가 뚫려 보인다 | 방 샘플의 모든 소켓 Wall을 닫아 두었는지 확인합니다. |
| 오브젝트 프리팹 오류가 난다 | 선택한 Kind에 필요한 `Enemy`, `TreasureChest`, `ScenePortal` 컴포넌트가 자식 포함 존재하는지 확인합니다. |
| Kill Lock 상자를 선택할 수 없다 | 상자 프리팹에 `ChestMonsterKillLock`이 있고 Chest Kind로 배치되었는지 확인합니다. |
| 복도가 보이지 않는다 | 복도 길이가 양수라면 Floor/Wall 타일 자동 선택 결과 또는 오버라이드를 확인합니다. |
| 같은 Seed인데 결과가 달라졌다 | 라이브러리 방 순서, 방 데이터, 가중치 또는 생성 설정이 변경되었는지 확인합니다. |
| 프로필을 적용했지만 게임 값이 바뀌지 않는다 | 프로필 안내문의 활성 씬 참조 수가 1 이상인지 확인하고, 이미 생성된 씬이 아니라 새로 진입한 복도에서 확인합니다. |
| 미리보기 표식이 갱신되지 않는다 | 스크립트 컴파일 또는 도메인 리로드 후 `동적 생성 미리보기`를 다시 누릅니다. |
| 미리보기에서는 되지만 게임에서 상호작용이 안 된다 | 미리보기는 게임플레이 프리팹을 실행하지 않습니다. 전용 절차 씬의 인프라와 Play Mode를 확인합니다. |

## 저장 전 체크리스트

- [ ] 올바른 테마 룸 라이브러리를 선택했다.
- [ ] Room Id가 라이브러리 안에서 고유하다.
- [ ] 방 역할과 등장 가중치가 의도와 맞다.
- [ ] 예약 크기가 실제 방의 가장 바깥쪽 타일을 포함한다.
- [ ] 예약 영역 밖의 불필요한 타일이 없다.
- [ ] 모든 소켓은 경계의 2칸이며 바깥쪽을 향한다.
- [ ] 모든 소켓 셀에 Floor와 Wall이 모두 있다.
- [ ] 연결되지 않은 소켓도 Wall로 닫혀 있다.
- [ ] 오브젝트 Placement Id가 방 안에서 고유하다.
- [ ] 모든 오브젝트 기준 셀이 Floor 위에 있다.
- [ ] Monster와 Kill Lock Chest 연결 수가 의도와 맞다.
- [ ] 함정·레버·퍼즐은 자체 완결형 Prop이고 내부 Anchor Slot Id가 사용 범위에서 고유하다.
- [ ] 런 중 보존이 필요한 Prop 내부 상태에 별도 캡처·복원 계약이 있다.
- [ ] 모든 Travel Slot Id가 방 안에서 고유하고 방식이 `Interaction`/`Trigger`/`ArrivalOnly` 의도와 맞다.
- [ ] 이동 편집기에서 올바른 Builder, Connection, A/B Side와 전환 연출을 연결했다.
- [ ] `ArrivalOnly` 연결의 역방향이 비활성이고 바인딩을 적용한 게임플레이 씬을 저장했다.
- [ ] 현재 방 포함 미리보기를 여러 Seed로 확인했다.
- [ ] 변경한 생성 수치를 실제 테마에서 사용할 경우 올바른 생성 프로필에 적용했다.
- [ ] 큰 방 또는 종단형 방이면 부분 생성 가능성을 확인했다.
- [ ] 전체 검증을 통과했다.
- [ ] 새 저장인지 원본 갱신인지 버튼과 대상 경로를 확인했다.

## 저장 후 Play Mode 체크리스트

- [ ] 전용 절차 복도 씬에서 방과 복도가 정상 생성된다.
- [ ] 연결된 소켓만 열리고 사용하지 않은 소켓은 막혀 있다.
- [ ] 문이 각 소켓 끝에 생성된다.
- [ ] 플레이어가 문을 지나 방 내부에 들어간 뒤 전투 문이 닫힌다.
- [ ] 방에 들어가기 전에는 몬스터가 생성되거나 다른 방에서 플레이어를 인식하지 않는다.
- [ ] 첫 번째·두 번째·세 번째 보스 진행도에서 같은 스폰 위치의 실제 몬스터 구성이 StageMonsterSet에 맞게 바뀐다.
- [ ] 문 밖에 걸친 몬스터 때문에 잘못 닫히지 않는다.
- [ ] 몬스터가 기존 `MonsterSpawner` 경로로 생성되고 처치 판정에 포함된다.
- [ ] Kill Lock 상자의 연출과 해금이 정상 동작한다.
- [ ] Portal, Chest, 복합 Prop의 상호작용이 정상 동작한다.
- [ ] 같은 Seed를 다시 생성했을 때 같은 레이아웃이 나온다.
