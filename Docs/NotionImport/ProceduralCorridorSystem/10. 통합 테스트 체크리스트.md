# 10. 통합 테스트 체크리스트

[← 시작 페이지](<./00. 절차적 복도 시스템.md>)

구현 완료 여부와 실제 플레이 품질은 별개입니다. 설치기 실행 뒤 아래 순서대로 한 런 전체를 확인합니다.

## 맵 생성

- [ ] Shadow, Dragon, Slime이 각각 목표 15개 방으로 생성된다.
- [ ] Start에서 Boss까지 이동 가능한 경로가 있다.
- [ ] 방·복도가 서로 겹치지 않고, 플레이어가 타일 밖으로 빠질 틈이 없다.
- [ ] 연결된 2칸 소켓만 열리고 사용하지 않은 소켓은 벽으로 막힌다.
- [ ] 큰 ㄴ자·ㄱ자 방과 가변 길이 복도가 정상 배치된다.
- [ ] 필수 Event 방이 프로필의 배치 정책을 만족한다.

## 전투와 보상

- [ ] 전투 방 안쪽에 진입한 뒤 문이 닫힌다.
- [ ] 문 밖 몬스터가 방 안 몬스터로 잘못 집계되지 않는다.
- [ ] 모든 대상 몬스터 처치 후 방 문이 열린다.
- [ ] Kill Lock 상자는 기존 연출과 함께 해제된다.
- [ ] 제물 보상 방의 내부 문과 보상 상자가 정상 동작한다.

## HUB와 보스

- [ ] 각 이동 방의 Room/Slot 바인딩이 올바른 Connection A/B Side와 현재 씬을 가리킨다.
- [ ] 모든 출발 방향에 의도한 전환 연출 프로필이 연결되어 있다.
- [ ] HUB의 세 게이트가 올바른 테마 복도로 이동한다.
- [ ] HUB→복도와 복도→HUB에서 같은 와이프 전환이 재생된다.
- [ ] 복도 Start 방으로 돌아왔을 때 플레이어 위치와 방향이 자연스럽다.
- [ ] Boss 포털이 올바른 보스 씬으로 이동한다.
- [ ] 해당 런에서 이미 처치한 보스는 재진입이 차단되고 안내 팝업이 표시된다.
- [ ] HUB의 기존 상호작용 포탈이 일반 테마가 아니라 고정 DemonkingCorridor 휴식 씬으로 이동한다.
- [ ] DemonkingCorridor의 기존 포탈이 DemonKing 보스 씬으로 이동한다.
- [ ] 폐기된 ProceduralDemonkingCorridor와 이전 두 Connection 방향으로는 진입할 수 없다.

## 복도 간 토관

- [ ] Shadow의 토관은 Slime의 Shadow 도착 방으로만 이동한다.
- [ ] Dragon의 토관은 Slime의 Dragon 도착 방으로만 이동한다.
- [ ] Slime 도착 지점에는 역방향 상호작용 수단이 없다.
- [ ] Slime 도착 지점은 `ArrivalOnly`이고 Connection의 B→A도 비활성이다.
- [ ] Slime→Shadow, Slime→Dragon, Shadow↔Dragon 우회 경로가 생기지 않는다.
- [ ] 출발 흡입 연출과 Slime 물 도착 연출이 올바른 앵커에서 재생된다.

## NPC

- [ ] 공사 NPC가 CycleDetour 지름길 방에 배치된다.
- [ ] 순간이동 NPC가 Start에서 그래프 거리 4 이상인 먼 막다른 방에 배치된다.
- [ ] 두 NPC의 대사와 선택지가 매번 정상 표시된다.
- [ ] 순간이동 도착 시 기존 물에서 튀어나오는 연출이 재생된다.

## 맵 보존

- [ ] 복도→HUB→같은 복도로 돌아와도 방 배치와 시드가 유지된다.
- [ ] 복도 간 토관 이동 후 되돌아와도 이미 방문한 복도의 배치가 유지된다.
- [ ] 처치한 몬스터와 획득한 상자 상태가 지원 범위 안에서 복원된다.
- [ ] 새 런 시작과 런 종료 시 이전 런의 복도 상태가 초기화된다.

## 테마

- [ ] 각 복도에 올바른 타일·몬스터·보상 오브젝트가 사용된다.
- [ ] Shadow에서 시야 제한과 어둠 기믹이 정상 동작한다.
- [ ] 세 테마의 문, 포털, 토관이 배경에 묻히지 않는다.
