# 09. 테마별 현재 구성

[← 시작 페이지](<./00. 절차적 복도 시스템.md>)

## 공통 구성

- 15개 방
- Start와 한 소켓 Boss 종단 방
- 직사각형 전투 방 3종
- 50×50 이상 ㄴ자·ㄱ자 전투 방
- 제물 석상·내부 문·보상 상자가 있는 Treasure 방
- 2칸 소켓·복도·문
- 방별 Monster Kill Lock 문과 상자 연결
- 전투 방 진입 후 현재 런 진행도에 맞춰 생성되는 몬스터
- HUB 왕복과 보스 이동 Endpoint
- `PreserveDuringRun`

세 테마의 전투 방은 개별 Goblin, Lizard, 체스말 프리팹을 고정 편성으로 사용하지 않습니다. 소형·대형 방별 Spawn Profile이 현재 Stage에 맞는 Common Melee, Ranged, Tank `StageMonsterSetSO`를 선택합니다. Room Template의 Monster 배치는 실제 종류가 아니라 스폰 위치와 폴백만 제공합니다.

## Shadow

- ShadowCorridor 타일과 공통 진행도 기반 몬스터 편성을 사용합니다.
- 씬 루트에 기존 그림자 복도의 시야 제한·어둠 인프라를 유지합니다.
- 폐기된 Slime행 토관 Event 방은 생성하지 않습니다.

## Dragon

- DragonCorridor 타일과 공통 진행도 기반 몬스터 편성을 사용합니다.
- 폐기된 Slime행 토관 Event 방은 생성하지 않습니다.

## Slime

- SlimeCorridor 타일과 공통 진행도 기반 몬스터 편성을 사용합니다.
- 공사 지름길·순간이동 NPC 방은 에셋만 남기고 생성 라이브러리와 필수 방에서 봉인합니다.
- Shadow와 Dragon에서 오던 토관 도착 전용 방도 생성하지 않습니다.

## DemonKing

- 일반 테마 절차 생성 대상이 아닙니다.
- 자동 `LobbyGate_demon_king` 트리거는 없습니다.
- HUB의 기존 상호작용 `ScenePortal`에서 고정 `DemonkingCorridor` 휴식 씬으로 직접 진입합니다.
- 포탈은 일반 스테이지가 없는 `DemonkingHubRouteCatalog`를 사용하므로 일반 테마 런 계획을 바꾸지 않습니다.
- 이 씬은 전투 스폰이 없고 기존 `CorridorToBoss` 포털로 최종 보스에 진입합니다.

## 테마 책임 분리

레이아웃 조립기는 테마를 알지 않습니다. 테마별 차이는 다음 데이터가 소유합니다.

- Room Theme Library
- Room Template의 타일과 오브젝트
- Dungeon Generation Profile
- 씬의 DungeonRoomBuilder 타일 팔레트와 시야 기믹
