# 13. 기술 참고

## 생성 데이터 흐름

`Room Template / Theme Library → Dungeon Generation Profile → Layout Generator → DungeonRoomBuilder → 런타임 방·복도·문·오브젝트`

- Template은 방의 경량 레이아웃 정보와 상세 구현 정보를 제공합니다.
- Profile은 방 수, 거리, 가지, 순환, 필수 방 정책을 제공합니다.
- Layout Generator는 테마를 모르고 점유 영역과 소켓으로 그래프를 조립합니다.
- Builder가 선택된 Template을 실제 타일맵과 런타임 오브젝트로 구현합니다.

## 이동 데이터 흐름

`Travel Slot → SceneConnectionSO Endpoint → SceneConnectionTravelService → 전환 연출 → 대상 씬 Arrival Slot`

- 출발점은 Interaction 또는 Trigger 모드를 사용합니다.
- 도착점은 `ArrivalOnly`로 만들 수 있습니다.
- 연결 방향은 데이터에 명시하며, 단방향 연결은 역연결을 자동 생성하지 않습니다.
- 복도 이탈 직전 런 상태를 캡처하고 재진입 시 같은 생성 결과 위에 복원합니다.

## 현재 검증 기준

- 절차 생성 Play Mode 테스트: 15/15 통과. 전투 방 지연 스폰·문 잠금 회귀 테스트 포함
- 세 테마 프로필: 방 15개, 최소 복도 길이 2, 복도 길이 변동 2
- 세 테마 재방문 정책: `PreserveDuringRun`
- HUB 게이트: Shadow, Dragon, Slime 세 개 모두 활성 설치
- HUB 상호작용 포탈: `DemonkingHubRouteCatalog`를 통해 `DemonkingCorridor` 직행
- 일반 보스 복도 간 직접 연결: 없음. 이전 토관·도착 방 에셋은 보존하되 생성 등록은 제거
- Slime 특수 NPC: 에셋은 보존하되 현재 생성 등록은 제거
- 최종 보스 경로: 전용 카탈로그의 일반 스테이지 0개, 고정 `DemonkingCorridor` 활성, 폐기된 절차 씬과 이전 연결 방향 비활성

자동 테스트 통과는 전체 플레이 검수 완료를 뜻하지 않습니다. 실제 릴리스 판단에는 [통합 테스트 체크리스트](<./10. 통합 테스트 체크리스트.md>) 결과를 함께 기록하세요.
