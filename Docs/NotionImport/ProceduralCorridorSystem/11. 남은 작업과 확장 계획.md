# 11. 남은 작업과 확장 계획

[← 시작 페이지](<./00. 절차적 복도 시스템.md>)

현재 시스템의 핵심 기능은 구현되어 있습니다. 아래 항목은 정식 플레이 흐름에 넣기 전에 마무리해야 할 통합·품질 작업입니다.

## 출시 전 반드시 남은 작업

### 1. HUB 게이트 최종 승인

세 게이트 오브젝트는 HUB에 활성 상태로 설치되어 있습니다. 기획자가 실제 플레이 화면을 보며 위치, 진입 방향, 2×2 트리거 범위, 다른 오브젝트와의 충돌을 최종 승인하고 미세 조정해야 합니다.

### 2. 정식 런 진행 문맥 연결

단순 씬 이동은 연결되어 있지만, 실제 게임의 Route Catalog와 Stage 진행 문맥에서 각 보스 테마 선택이 정확히 기록되는지 검증해야 합니다. 보스 처치 기록과 일반 테마별 독립 런 흐름을 확인하고, HUB의 기존 포탈은 `DemonkingHubRouteCatalog` 하나만 활성화하는지 확인합니다.

고정 `DemonkingCorridor`는 HUB 포탈에서 직접 진입합니다. 폐기된 `ProceduralDemonkingCorridor` Build Settings 항목과 이전 두 연결 방향은 비활성화되어 있으므로, 전체 런 검수에서는 이전 경로로 우회 진입할 수 없는지도 확인합니다.

### 3. 전체 Play Mode 왕복 테스트

[통합 테스트 체크리스트](<./10. 통합 테스트 체크리스트.md>)를 한 런 처음부터 끝까지 수행해야 합니다. 자동화된 절차 맵 테스트는 통과했지만, 입력·카메라·UI·연출을 포함한 실제 플레이 검수는 별도입니다.

### 4. 연출 미세 조정

HUB 전환 와이프, 토관 흡입 앵커, Slime 물 도착 앵커, 플레이어 등장 방향과 대기 시간을 실제 아트 기준으로 조정합니다. 구조 변경 없이 데이터와 씬 배치로 해결하는 것이 원칙입니다.

## 이후 확장 후보

### 영구 해금 숏컷 방

현재 `PreserveDuringRun`은 같은 런 안의 상태를 보존합니다. 런을 넘어 영구 유지되는 숏컷은 별도의 영구 진행 키, 저장 데이터, 잠금 해제 프레젠테이션이 필요합니다.

### NPC·퍼즐의 임의 상태 보존

현재 보존 범위 밖의 커스텀 컴포넌트 상태가 필요하면 각 오브젝트가 안정적인 ID와 상태 캡처·복원 계약을 제공하도록 확장합니다. 특정 NPC를 이름으로 찾아 하드코딩하지 않습니다.

### 더 복잡한 복도 연결

현재 복도 간 연결은 기획에 맞춘 `Shadow → Slime`, `Dragon → Slime` 단방향 두 개입니다. 연결이 늘어나면 방향 그래프, 중복 목적지, 도착 방 예약, 순환 방지를 데이터 검증 단계에서 다뤄야 합니다.
