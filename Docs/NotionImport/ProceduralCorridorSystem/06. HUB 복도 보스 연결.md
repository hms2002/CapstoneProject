# 06. HUB·복도·보스 연결

[← 시작 페이지](<./00. 절차적 복도 시스템.md>)

## 연결 데이터의 역할

`SceneConnectionSO` 하나는 두 씬 Endpoint와 A→B, B→A 방향 설정을 보관합니다.

- 목적 씬과 Endpoint Id
- 방향 사용 여부
- 런 시작·종료 동작
- 플레이어 상태 보존 여부
- 전환 연출 프로필
- 보스 처치 여부 같은 사용 조건

방 템플릿은 목적 씬을 직접 저장하지 않습니다. `(Room Id, Slot Id)`와 씬의 Travel Endpoint Binding이 연결 에셋의 A/B 측을 결합합니다.

일반 제작에서는 Room Piece Editor의 `이동 연결·연출 편집기 열기` 또는 `Tools > Dungeon > Procedural Travel Binding Editor`를 사용합니다. 대상 `DungeonRoomBuilder`, Room/Slot, Connection과 A/B Side를 선택하고 방향 정책과 연출을 확인한 뒤 바인딩을 적용합니다. 현재 씬과 Connection Endpoint의 씬 이름이 다르면 경고가 표시됩니다. 적용 후 게임플레이 씬은 직접 저장합니다.

## HUB↔복도

| 방향 | 런 동작 | 연출 |
| --- | --- | --- |
| HUB→복도 | 런이 비활성이면 `StartRun` | 우→좌 검정 와이프 |
| 복도→HUB | `None` | 같은 우→좌 검정 와이프 |

복도→HUB는 런을 종료하지 않습니다. 따라서 같은 런 중 다시 복도에 들어가면 보존된 맵을 복원할 수 있습니다. HUB→복도의 `StartRun`도 이미 런이 활성 상태라면 다시 초기화하지 않습니다.

## 복도→보스

- 각 Boss 방의 `BossGate`는 `Interaction` 방식입니다.
- 보스 씬은 `PlayerSpawnPoint` 위치에 ArrivalOnly Endpoint를 가집니다.
- 해당 테마 보스를 현재 런에서 이미 처치했다면 이동을 차단하고 공통 팝업을 표시합니다.
- 보스 이동은 일반 `ScenePortal` 하드코딩이 아니라 연결 데이터와 안정적인 테마 ID를 사용합니다.

## HUB 게이트 현재 상태

세 게이트 오브젝트는 `ProtoTypeHub`에 활성 상태로 배치되어 있습니다.

- Endpoint
- 자동 Trigger
- `2×2` Trigger Collider
- 연결 에셋과 A측 바인딩
- 출발·도착 Anchor

기획자가 최종 위치, 방향, Collider 크기와 플레이 감각을 승인해야 합니다. 또한 정식 런 진행 순서를 사용할 경우 선택한 게이트가 올바른 Route Catalog·현재 Stage 문맥을 준비하는지 최종 통합 검증이 필요합니다.

HUB 게이트 설치기는 이미 존재하는 게이트의 위치와 활성 상태를 보존합니다. 누락된 게이트만 비활성 배치용 오브젝트로 만들므로 기획자가 위치를 정한 뒤 활성화해야 합니다.

최종 DemonKing은 자동 트리거 게이트 대상이 아닙니다. 대신 HUB의 기존 상호작용 `ScenePortal`이 `DemonkingHubRouteCatalog`를 사용합니다. 이 전용 카탈로그는 일반 스테이지 수가 0이고 `DemonkingRouteSet`만 final로 가져, 포탈 사용 시 곧바로 고정 `DemonkingCorridor`로 이동합니다.

폐기된 `ProceduralDemonkingCorridor` Build Settings 항목과 이전 HUB↔절차 복도·절차 복도↔보스 `SceneConnectionSO` 방향은 계속 비활성 상태로 보존합니다. DemonKing 직행은 그 레거시 연결을 되살리지 않고 기존 `ScenePortal`과 Route Catalog 경로를 사용합니다.
