# 08. 런 중 맵 상태 보존

[← 시작 페이지](<./00. 절차적 복도 시스템.md>)

## 현재 정책

Shadow, Dragon, Slime은 모두 `PreserveDuringRun`을 사용합니다.

- 복도→HUB 복귀
- 같은 런에서 다시 복도 진입

위 상황에서는 처음 생성된 Seed를 재사용해 같은 맵을 다시 구성합니다.

## 보존되는 것

- 방 선택과 배치
- 복도 연결과 길이
- 생성 오브젝트의 존재 여부
- 생성 오브젝트의 활성 상태
- 열린 상자 상태
- 열린 상자에 남은 보상과 유물 레벨

전투 방에 진입하기 전에는 몬스터가 생성되지 않습니다. 진입 후 생성된 몬스터는 해당 스폰 지점의 안정적인 Placement Id를 이어받으므로, 처치된 몬스터는 같은 런에서 복도를 다시 구성할 때 다시 제거됩니다.

## 초기화되는 시점

- 새 런 시작
- 런 종료
- 개발용 직접 시작 초기화

각 테마는 별도의 상태 ID를 사용하므로 Shadow 상태가 Dragon이나 Slime 상태를 덮어쓰지 않습니다.

## 씬을 계속 보관하는 방식은 아닙니다

씬을 메모리에 남겨 두지 않습니다.

1. 정식 씬 이동 직전에 현재 생성 오브젝트 상태를 저장합니다.
2. 목적 씬을 로드합니다.
3. 다시 돌아오면 같은 Seed로 맵을 재생성합니다.
4. 안정적인 방·Placement Id를 기준으로 상태를 복원합니다.

따라서 방이나 Placement Id를 수정한 버전을 런 도중 적용하면 기존 런 상태가 맞지 않을 수 있습니다.

## 현재 보존 범위의 한계

임의의 모든 컴포넌트 내부 값이 자동 저장되는 것은 아닙니다. 특수 레버, 함정 단계, 커스텀 퍼즐처럼 추가 상태가 필요하면 해당 기능이 별도의 저장·복원 계약을 제공해야 합니다.
