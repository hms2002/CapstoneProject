# 03. 방 데이터와 제작 규칙

[← 시작 페이지](<./00. 절차적 복도 시스템.md>)

## 방 데이터는 두 부분으로 나뉩니다

### 레이아웃 조립용 데이터

- Room Id와 역할
- 전체 방을 감싸는 직사각형 예약 영역
- 등장 가중치와 난이도 단계
- 출입구 소켓 위치, 방향과 폭
- 그래프 배치 제약

### 방 구현용 데이터

- UnderFloor, Floor, FloorDetail, GroundDecoration, Wall, WallDetail, Foreground, OverlayFX 고정 타일 슬롯
- Warrior/Mage/Tank 공통 역할 또는 스테이지 고정 Monster 스폰 위치, Chest, Portal, Prop 배치
- Kill Lock 상자 연결
- 씬 이동 Endpoint 슬롯
- 자체 완결형 Prop 프리팹 내부의 런타임 앵커

레이아웃 조립기는 테마나 몬스터 종류를 알지 않습니다. 선택한 테마 라이브러리가 제공한 방의 크기와 소켓만 사용해 배치를 결정합니다.

## 예약 영역

방의 실제 모양과 관계없이 가장 바깥쪽 타일까지 포함하는 직사각형을 예약합니다.

- ㄴ자·ㄱ자 방도 바깥 직사각형 전체를 예약합니다.
- 빈 안쪽 모서리에는 Floor를 칠하지 않습니다.
- 단순한 직사각형 충돌 검사 덕분에 큰 비정형 방도 안정적으로 배치할 수 있습니다.

## 소켓 규칙

- 모든 소켓 폭은 현재 2칸입니다.
- 소켓은 방 경계에 있어야 합니다.
- 소켓 두 셀에는 Floor와 Wall이 모두 있어야 합니다.
- 방 샘플에서는 소켓을 미리 뚫지 않습니다.
- 맵 생성 시 연결된 소켓만 열고, 사용하지 않은 소켓은 Wall과 물리 Blocker로 막습니다.
- 문은 복도 중앙이 아니라 연결된 각 소켓 끝에 생성됩니다.

## 방 역할

| 역할 | 의미 |
| --- | --- |
| `Start` | 맵 시작 방. 생성기가 별도로 한 개 선택합니다. |
| `Combat` | 일반 전투 확장 방 |
| `Treasure` | 보상·제물 방 |
| `Event` | NPC, 이동, 특수 이벤트 방 |
| `Shop` | 향후 상점 방 |
| `Boss` | 종단 보스 연결 방 |

`Start`, `Boss`, `Exit`은 반드시 포함할 방 목록에 넣지 않습니다. 생성기가 별도의 구조 역할로 관리합니다.

## 오브젝트와 이동 슬롯

| 데이터 | 식별자 | 용도 |
| --- | --- | --- |
| 일반 오브젝트 | Placement Id | 몬스터·상자·프롭 상태와 Kill Lock 연결 |
| 씬 이동 지점 | Slot Id | 방 데이터와 최종 `SceneConnectionSO` 바인딩 분리 |
| Prop 내부 방/던전 앵커 | Anchor Slot Id | NPC, 순간이동, 런타임 모듈의 위치 참조. 독립 방 데이터가 아니라 프리팹 내부 구성입니다. |

같은 방 안에서 각 ID는 고유해야 합니다. `PreserveDuringRun`은 이 안정적인 ID를 사용하므로 진행 중인 런에서 ID를 바꾸면 기존 상태를 복원하지 못할 수 있습니다.

`Monster` 배치는 두 방식입니다. `공통 역할`은 Warrior/Mage/Tank 역할과 위치를 저장하고 CommonMelee/CommonRanged/CommonTank `StageMonsterSetSO`에서 현재 보스 처치 수의 몬스터를 고릅니다. `스테이지 몬스터`는 기획자가 지정한 Enemy 프리팹과 위치를 저장하며 진행도와 관계없이 같은 적을 생성합니다. 두 방식 모두 전투 방 안쪽에 처음 진입할 때 생성됩니다.

각 `RoomThemeLibrarySO`는 해당 테마에서 빠르게 선택할 수 있는 스테이지 몬스터 프리팹 카탈로그도 보관합니다. 방 제작 툴은 이 카탈로그와 기존 방의 고정 몬스터를 합쳐 이전과 같은 `추천 프리팹` 드롭다운을 제공합니다. 레이아웃 조립기는 이 카탈로그를 읽지 않습니다.

함정, 레버와 퍼즐은 현재 별도 Kind가 아니라 완성된 `Prop` 프리팹으로 배치합니다. 필요한 `ProceduralRoomAnchor`와 내부 참조는 그 프리팹이 소유합니다. 임의 컴포넌트의 단계·작동 여부는 자동 보존되지 않으므로 런 중 복원이 필요한 콘텐츠는 별도의 안정적인 상태 캡처·복원 계약을 제공해야 합니다.

`GroundProp`도 별도 Tilemap이 아니라 `Prop` 배치입니다. 개별 충돌과 물리 레이어는 프리팹이 소유합니다. 장식 Tilemap은 물리 Ground 스캔에서 제외되고, Wall만 Tilemap Collider를 가집니다.
