# 절차적 복도 시스템

> 기획자·레벨 디자이너·프로그래머가 함께 보는 현재 구현 기준 문서입니다. 기준일: 2026-08-30

## 한눈에 보기

- HUB에서 Shadow, Dragon, Slime 세 일반 보스 테마 복도로 진입합니다.
- 각 복도는 준비된 방 데이터를 15개 방 그래프로 조립합니다.
- Start 방은 HUB 왕복, Boss 방은 해당 보스 씬 진입을 담당합니다.
- Shadow와 Dragon에는 Slime으로 향하는 단방향 토관 방이 반드시 배치됩니다.
- Slime에는 두 토관의 도착 방과 공사·순간이동 NPC 방이 각각 반드시 배치됩니다.
- 같은 런에서는 방문한 복도의 맵 구성과 지원되는 오브젝트 상태를 보존합니다.
- 최종 DemonKing은 HUB의 기존 상호작용 포탈에서 선택하며 고정 휴식 씬 `DemonkingCorridor`를 거칩니다.

## 현재 완료 범위

| 구분 | 상태 |
| --- | --- |
| 세 테마 절차 맵 생성 | 구현 및 설치기 검증 완료 |
| HUB↔복도 전환 | 양방향 와이프 연출 적용 |
| 복도→보스 | 데이터 기반 포털 및 보스 처치 잠금 적용 |
| Shadow/Dragon→Slime | 단방향 토관 구현 완료 |
| Slime 특수 NPC 방 분리 | 공사·순간이동 방 분리 완료 |
| 같은 런 맵 보존 | `PreserveDuringRun` 자동 회귀 테스트 완료 · 전체 왕복 플레이 검수 대기 |
| 최종 DemonKing 동선 | 기존 HUB 포탈 직행 · 고정 전투 없는 휴식 복도 유지 · 폐기된 절차 씬/연결 비활성 |
