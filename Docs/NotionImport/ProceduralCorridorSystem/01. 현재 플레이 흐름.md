# 01. 현재 플레이 흐름

[← 시작 페이지](<./00. 절차적 복도 시스템.md>)

## 전체 흐름

```text
HUB
 ├─ Shadow 절차 복도 ─→ Shadow 보스
 │        └─ 토관 ─→ Slime 절차 복도
 ├─ Dragon 절차 복도 ─→ Dragon 보스
 │        └─ 토관 ─→ Slime 절차 복도
 ├─ Slime 절차 복도 ─→ Slime 보스
 └─ 기존 상호작용 포탈 ─→ DemonkingCorridor 고정 휴식 씬 ─→ DemonKing 보스
```

## HUB에서 선택 가능한 복도

| HUB 게이트 | 목적지 | 현재 상태 |
| --- | --- | --- |
| `LobbyGate_shadow` | `ProceduralShadowCorridor` | 씬에 배치·활성화됨 |
| `LobbyGate_dragon` | `ProceduralDragonCorridor` | 씬에 배치·활성화됨 |
| `LobbyGate_slime` | `ProceduralSlimeCorridor` | 씬에 배치·활성화됨 |
| 기존 `ScenePortal` | `DemonkingCorridor` | DemonKing 전용 카탈로그로 연결됨 |

DemonKing용 자동 `LobbyGate_demon_king` 트리거는 만들지 않습니다. HUB의 기존 상호작용 `ScenePortal`이 일반 스테이지가 없는 전용 Route Catalog를 시작해 고정 휴식 복도로 이동합니다.

## 이동 방향 규칙

- HUB↔복도는 양방향입니다.
- 복도→보스 연결은 해당 런에서 보스를 이미 처치했다면 사용할 수 없습니다.
- Shadow→Slime과 Dragon→Slime은 단방향입니다.
- Slime→Shadow, Slime→Dragon, Shadow↔Dragon 이동은 없습니다.

## 전환 연출

- HUB→복도와 복도→HUB는 같은 우→좌 검정 와이프를 사용합니다.
- HUB의 DemonKing 포탈은 기존 포탈 흡입·회전 진입 연출을 유지합니다.
- 토관 출발은 플레이어 흡입·회전 연출을 사용합니다.
- Slime 도착은 기존 물에서 튀어나오는 VFX와 이동 연출을 재사용합니다.
