# 05. 오브젝트와 Kill Lock

[← 시작 페이지](<./00. 절차적 던전 방 제작 툴.md>)

## 오브젝트 배치 순서

1. `4. 오브젝트`를 엽니다.
2. `종류`를 선택합니다.
3. Monster는 `공통 역할` 또는 `스테이지 몬스터` 방식을 고릅니다. 공통 역할은 Warrior/Mage/Tank를, 스테이지 몬스터는 고정 프리팹을 지정합니다. 다른 Kind는 `추천 프리팹` 또는 `배치할 프리팹`을 사용합니다.
4. `방 중앙에 배치 후 Scene View에서 이동`을 누릅니다.
5. Scene View에서 위치, 회전과 크기를 조절합니다.
6. Placement Id가 방 안에서 고유한지 확인합니다.

스테이지 몬스터의 추천 프리팹은 선택한 테마 라이브러리에 등록된 허용 몬스터와 기존 방에서 사용한 고정 몬스터를 합쳐 중복 없이 이름순으로 보여줍니다. 목록에 없는 프리팹도 직접 지정할 수 있습니다. 다른 Kind는 기존 방에서 같은 종류를 모아 보여줍니다.

## 종류별 조건

| 종류 | 필수 구성 | 런타임 생성 방식 |
| --- | --- | --- |
| `Monster / 공통 역할` | `Warrior`, `Mage`, `Tank` 역할 선택 | 방 입장 시 역할별 StageMonsterSet의 현재 진행도 몬스터 생성 |
| `Monster / 스테이지 몬스터` | 자식 포함 `Enemy`가 있는 고정 프리팹 | 방 입장 시 지정한 몬스터를 그대로 생성 |
| `Chest` | 자식 포함 `TreasureChest` | 완성된 프리팹 인스턴스 |
| `Portal` | 자식 포함 `ScenePortal` | 완성된 프리팹 인스턴스 |
| `Prop` | 별도 공통 필수 컴포넌트 없음 | 완성된 프리팹 인스턴스 |

## 배치 데이터

Transform을 움직이면 Grid 기준 Local Cell, 셀 중심 Offset, 로컬 회전 각도와 Scale로 저장됩니다.

오브젝트 기준 셀은 예약 영역 안이며 Floor 위여야 합니다. 큰 프리팹의 전체 스프라이트나 Collider가 벽 밖으로 나가는지는 자동으로 확인하지 않습니다.

전투 방의 일반 편성은 `공통 역할`로 배치합니다. Warrior는 `CommonMelee`, Mage는 `CommonRanged`, Tank는 `CommonTank` StageMonsterSet에 자동 연결되며, 툴 카드에서 보스 0·1·2마리 처치 시 실제 몬스터를 확인할 수 있습니다.

진행도와 관계없이 그 방에 반드시 같은 적이 필요하면 `스테이지 몬스터`를 선택하고 해당 `Enemy` 프리팹을 직접 지정합니다. 두 방식 모두 맵 생성 시에는 지연 스폰 지점만 만들어지고, 플레이어가 방 안쪽에 완전히 진입한 뒤 VFX와 함께 생성됩니다.

## 씬 이동 슬롯과 도착 위치

1. `매개체 방식`과 필요하면 `매개체 프리팹`을 고릅니다.
2. `Trigger` 방식이면 `Trigger Size (월드 단위)`로 실제 진입 판정 크기를 정합니다. 이 값은 매개체 Transform Scale과 독립적입니다.
3. `이동 슬롯을 방 중앙에 추가`를 누르고 Scene View에서 출발 매개체 위치를 정합니다. 파란 사각형이 실제 Trigger 범위입니다.
4. 배치 후에는 슬롯 카드의 `Trigger Size`로 판정 크기를 다시 수정할 수 있습니다.
5. 이동 후 플레이어를 다른 위치에 세우려면 `도착 위치 별도 지정`을 켭니다.
6. 카드의 `Select`를 누른 뒤 Scene View의 녹색 도착 핸들을 안전한 Floor 셀로 옮깁니다.
7. 정확한 좌표가 필요하면 `도착 Local Cell`과 `도착 Cell Offset`을 직접 입력합니다.

옵션을 끄면 매개체 Transform 또는 매개체 프리팹의 기존 Arrival Anchor를 사용합니다. 옵션을 켜면 방 데이터의 녹색 도착점이 우선합니다. 목적 씬과 이동 연출은 방에 저장하지 않으며, 방 저장 후 `이동 연결·연출 편집기`에서 씬별로 바인딩합니다.

## Placement Id

Placement Id는 한 방 안에서 고유해야 합니다.

- `Monster_01`
- `Monster_02`
- `KillLockChest_01`
- `ExitPortal_01`

Monster가 상자를 참조할 때도 이 ID를 사용하므로, 상자 ID를 변경했다면 연결을 다시 확인합니다.

## Kill Lock 상자 연결

1. `ChestMonsterKillLock`이 이미 구성된 상자 프리팹을 Chest로 배치합니다.
2. 상자의 Placement Id를 설정합니다.
3. 각 Monster 카드의 `Kill Lock Chest`에서 해당 상자를 선택합니다.
4. 상자 카드의 `Linked Monsters` 수를 확인합니다.

> Kill Lock 동작과 연출은 상자 프리팹이 소유합니다. 툴이 일반 상자에 컴포넌트나 연출을 임의로 추가하지 않습니다.

## 복합 Prop

제물 석상, 내부 잠금 문, 보상 상자처럼 서로 강하게 연결된 구성은 완성된 복합 프리팹 하나를 Prop으로 배치할 수 있습니다.

- 내부 참조와 상호작용 규칙은 프리팹이 소유합니다.
- 방 데이터는 프리팹과 위치만 저장합니다.
- 저장 후 Play Mode에서 실제 상호작용을 확인합니다.

## 함정·레버·퍼즐과 런타임 앵커

함정, 레버와 퍼즐은 현재 별도 Kind가 아니라 자체 완결형 `Prop` 프리팹으로 배치합니다.

- 필요한 `ProceduralRoomAnchor`는 해당 Prop 프리팹 내부에 둡니다.
- 앵커는 독립적인 `RoomBuildData` 목록이 아니므로 툴에서 단독 배치하지 않습니다.
- 내부 Anchor Slot Id는 그 기능이 검색하는 범위에서 고유하게 유지합니다.
- 임의 컴포넌트의 단계·작동 여부는 자동 보존되지 않습니다. 런 중 복원이 필요하면 프리팹이 안정적인 ID와 상태 캡처·복원 계약을 제공해야 합니다.

## 완료 조건

- [ ] 모든 Placement Id가 고유하다.
- [ ] 공통 역할 Monster는 StageMonsterSet, 스테이지 Monster는 유효한 Enemy 프리팹이 있다.
- [ ] 모든 기준 셀이 Floor 위에 있다.
- [ ] 큰 프리팹이 벽과 출입구를 막지 않는다.
- [ ] Monster와 Kill Lock Chest 연결 수가 의도와 맞다.
- [ ] 공통 역할 Monster에 Warrior/Mage/Tank와 해석 가능한 StageMonsterSet이 표시된다.
- [ ] 스테이지 고정 Monster에 의도한 프리팹이 표시된다.
- [ ] 역할별·고정 몬스터 지점 수와 위치가 의도한 방 편성과 일치한다.
- [ ] 방 진입 전에는 몬스터가 생성되지 않는다.
- [ ] 함정·레버·퍼즐 Prop의 내부 참조와 Anchor Slot Id가 올바르다.
- [ ] 런 중 보존이 필요한 내부 상태의 캡처·복원 계약을 확인했다.
- [ ] 별도 도착점을 사용한다면 녹색 핸들이 방 bounds 안의 Floor 셀에 있다.
