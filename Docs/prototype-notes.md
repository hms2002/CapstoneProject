# 프로토타입 메모

## 현재 확인된 프로토타입 선택

- 보스 보상 처리는 아직 프로토타입 우선 흐름이다.
- 예전 `BossTalkManager` 계열은 레거시 코드다. (삭제 가능)
- 현재 방향은 `BossEncounterDirector` 기반 흐름이다.
- 최종 보스 결과창 연출은 아직 완성되지 않았다.
- 추후 결과창에서 복귀 버튼을 눌러 허브로 돌아가는 구조를 목표로 한다.

## 현재 의도된 미구현 영역

- 패배 루프는 아직 정식 구현 전이다.
- 유해 업그레이드 modifier는 아직 구현하지 않았다.
- 일부 업그레이드 effect 카테고리는 아직 자리만 잡혀 있거나 placeholder 상태다.
- `SceneTransitionPolicyResolver`는 구조 대비 실제 사용 범위가 아직 작다.
- 런 종료 시 결과창 구현은 프로토타입이기 때문에 구현 전이다.

## 현재 제약 조건

- 허브 복귀 시 런 인벤토리와 임시 상태는 초기화되어야 한다.
- 영구 해금과 영구 성장 요소는 유지되어야 한다.
- 런 경로 생성은 동적이어야 한다.
- 허브 시작 포탈은 서로 다른 route catalog를 가질 수 있다.

## 나중에 다시 볼 영역

### 업그레이드 effect

- 구매한 node ID 재적용 방식은 해금형 effect에는 잘 맞는다.
- 모든 effect를 플레이어를 통해 재적용하는 방식은 월드 modifier, 런 modifier에는 한계가 있다.
- 유해와 루팅 업그레이드를 확장하기 전에 이 구조를 다시 검토해야 한다.

### 루팅 및 유해

- 유해 기본 드랍은 데이터 주도 구조다.
- 업그레이드 기반 유해 보너스는 아직 연결되지 않았다.
- 유물 rarity 로직은 최근 수정되었으므로, 새 유물 추가 시 회귀 확인이 필요하다.

### 스폰 및 복원

- 허브 스폰 포인트는 `ResetToSceneDefault`를 사용해야 한다.
- 전투 이동용 스폰 포인트는 `RestorePendingState`를 사용해야 한다.
- 허브 복귀 동작을 바꾸면 플레이어 상태 이어받기 가정을 다시 점검해야 한다.

## 이후 작업 체크리스트

- 이 변경은 허브 전용 로직인가, 런 로직인가
- 이 데이터는 영구 데이터인가, 런 임시 데이터인가
- 이 effect는 플레이어에 적용되는가, 런 규칙에 적용되는가, 루팅 규칙에 적용되는가
- 이 값은 씬 전환 후 복원되어야 하는가, 허브 복귀 시 초기화되어야 하는가
- 이 처리는 프로토타입 우회인가, 장기 구조의 일부인가
