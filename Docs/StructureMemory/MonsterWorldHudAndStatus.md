# Monster World HUD And Status

## Purpose and ownership

The authored `Assets/_Project/Prefabs/UI/MonsterWorldHud.prefab` displays HP under a monster and left-aligned status icons below HP. `MonsterStackStatusWorldView` reads AttributeSet and MonsterStatusRuntime; it creates no runtime UI hierarchy and owns no combat timers or stacks.

- `Runtime/Features/Monsters/Common/MonsterSizeProfile.cs`: explicit Small/Medium/Large, health visibility and authored ground anchor. Widths are 75/100/140 UI units (world scale 0.014); icon size, font size and bar height stay fixed.
- `Runtime/Features/Combat/Status/MonsterStatusRuntime.cs`: per-target registration, active lookup and clear. Burn retains stack/damage ownership. Electrocuted projects the existing target GameplayEffectRunner's configured effect remaining time, including refresh and cleanse.
- `Runtime/Core/Status/IMonsterStackStatusSource.cs`: neutral IMonsterStatusSource contract, replacing the former global UI playback backend.
- `Runtime/Features/Combat/Status/Burn/BurnStatus2D.cs`: registers with the target hub; no longer attaches a private world view. Existing formulas, 99 cap, live source modifiers and consumption APIs remain.
- `Runtime/Features/Enemies/Common/Enemy.cs`: clears the hub synchronously after marking death, before subclass death callbacks. This replaces the boss-only Burn special case.
- `Runtime/UI/Combat/StackStatus/MonsterStackStatusWorldView.cs`: serially authored Burn and Electrocuted slots; orange stacks and dark yellow remaining seconds, black outlined material. Hide inactive slots and compact from the left. HUD rotation/scale compensate for parent transform.

Paths above are relative to `Assets/_Project/`.

## Authoring and extension

`Editor/Tools/Monsters/MonsterWorldHudAuthoring.cs` exposes `Tools/Authoring/Build Approved Monster World HUD`, builds the shared prefab/material and connects the named 19 monster, 6 boss and 1 training dummy prefabs. Existing anchors are preserved. Inspect anchor placement on the actual sprite in Unity. New monsters need the same three references. The separate common-monster generator does not automatically invoke this installer; run HUD authoring after creating a new covered prefab.

A new status implements IMonsterStatusSource and registers with the target hub; add an authored slot to the HUD. No gameplay rules belong in the view. The existing GE_ElectrocutedStatus remains four seconds and retains discharge targeting/VFX. No new electrocution damage or control rules were introduced.

## Lifecycle and verification limits

Death clears effects/stacks before further Burn pulse processing; disable clears the status hub and Burn stacks, so re-enable does not revive an old burn. Explicit cleanse of a living target leaves the timed effect projection available for later applications. UI unsubscribes on disable.

Unity authoring validation passed for all 19 prefab connections. MSBuild passed for UI and Editor, including Core/Gameplay dependencies. Play Mode tests exist in `Tests/PlayMode/Procedural/MonsterWorldHudStatusTests.cs` but were not executed. Actual combat readability, anchor offsets and runtime rendering still require Play Mode confirmation.

Architecture/Contracts promotion candidate only after runtime verification; no source-of-truth document was rewritten.

## Approved visual correction (2026-09-16)

The current shared HUD uses original bitmap digits in `Assets/_Project/Art/Font/MonsterStatusPixelNumbers.asset`, generated by the authoring tool. Only 0-9, decimal point and lowercase s are authored; do not use this font for general labels. RGBA atlas pixels contain white glyph faces and a one-pixel black outline; UI/Default multiplies the faces by each status color while preserving black, with Point texture filtering. Font size is 14 and icon rects are 20 units. Status slots reserve 44/62 units with a 5-unit gap.

HP is square UI geometry with black outer border, gray frame, dark track, red fill and a lighter top strip. The runtime changes the fill RectTransform's horizontal anchor; no default rounded sprite is used. Bar height is 10 units. The authoring tool also exports an isolated actual Unity prefab render to `Temp/MonsterWorldHud-style-preview.png`; this render was visually inspected. Live gameplay scale and camera readability remain unverified.
## Damage feedback and boss status migration (2026-09-17)

The shared HUD contains a white DamageTrail Image behind the red fill. Health damage immediately moves red, holds the current white edge for 0.3 seconds after the latest hit, then interpolates it to health over 0.5 seconds. A new hit preserves the currently displayed trail and restarts the hold. Healing and maximum-health rescaling synchronize both fills; enable resets presentation state. These are presentation timers only.

Unity authoring and reference validation passed for 19 monsters and 6 bosses. The editor validation exercised the production private presentation methods for immediate red decrease, hold, interpolation, repeat damage and healing. The generated prefab render was inspected. Live Play Mode combat and boss anchor positions have not been verified.

The view resolves AttributeSet and MonsterStatusRuntime from the parent MonsterSizeProfile, allowing TrainingDummy2D targets without Enemy inheritance. Enemy death subscriptions/checks remain conditional. The dummy retains its existing damage readout and never-die behavior; no runtime HUD objects are created.
