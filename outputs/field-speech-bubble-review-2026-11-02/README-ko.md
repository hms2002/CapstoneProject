# 필드 대사 말풍선 — 첨부 디자인의 실제 셰이더 비교

## 결론

첨부 디자인은 같은 19×16px이므로 기존 9분할 틀에 넣을 수 있다. 다만 **현재 설정에서 PNG만 교체하면 직접 그린 외곽선과 아래 음영은 보존되지 않는다.** 색상 읽기만 켜면 직접 그린 선과 기존 셰이더 외곽선이 함께 표시된다. 시각적 의도가 그대로 유지되는 단순 교체는 아니다.

현재 구조에서 권하는 조합은 **원본의 알파 모양 + 첨부한 불투명 RGB 음영 + 기존 셰이더가 만드는 테마 외곽선**이다. 비교표의 ‘권장 조합’은 이 조건을 검증 전용 메모리 텍스처로 구성한 것이다. 게임의 PNG, 프리팹, 셰이더, 코드에는 반영하지 않았다.

## 비교한 다섯 방식

| 방식 | 이미지 RGB 사용 | 자동 외곽선 | 결과 |
| --- | --- | --- | --- |
| 기존 원본 | OFF | ON | 현재 표시 기준 |
| 첨부본 그대로 교체 | OFF | ON | 직접 그린 선·음영의 RGB 차이가 사라지고, 그 선까지 배경 모양으로 채워짐 |
| 첨부 색상 읽기 ON | ON | ON | 직접 그린 어두운 선 바깥에 테마 외곽선이 추가되어 두 겹으로 보임 |
| 자동 외곽선 OFF | ON | OFF | 직접 그린 선을 사용하나 배경 테마색과 알파가 선에도 적용됨. 캐릭터별 테두리색은 사용되지 않음 |
| 권장 조합, 게임 미적용 | ON | ON | 직접 그린 외곽선을 제외하고 음영만 사용. 테두리색은 기존 캐릭터 테마가 담당 |

여기서 ON/OFF는 검증용 머티리얼 설정이다. 게임은 `SpeechBubble.cs`가 표시할 때 `backgroundTextureInfluence`를 다시 적용하므로, 머티리얼의 Texture Influence만 바꾸면 실행 중 0으로 되돌아간다. 실제 적용 시에는 프리팹의 설정을 함께 검토해야 한다. 자동 외곽선을 끄는 비교는 `_OutlineThickness=0`이며 기존 머티리얼은 바꾸지 않았다.

## 왜 이런 결과가 나오는가

첨부 PNG의 색상은 흰색 145픽셀, 아래 음영 `#CECFD7` 15픽셀, 어두운 선 `#363232` 53픽셀, 완전 투명 91픽셀이다. 색이 있는 픽셀의 알파는 전부 255다. 원본의 불투명 160픽셀 위치는 첨부본의 흰색 145 + 음영 15 위치와 일치하고, 추가된 선 53픽셀은 기존 알파 모양 바깥에 있다.

`UIAlphaOutline.shader`는 이미지 RGB를 배경색과 곱한다. 현재 프리팹의 Texture Influence는 0이므로 RGB 대신 흰색을 사용하고 알파만 읽는다. 따라서 첨부 선과 음영도 배경색으로 채워진다. Texture Influence를 1로 바꾸면 흰 부분은 테마 배경색, 회색 음영은 그 배경색을 어둡게 한 색, 어두운 선은 더욱 어두운 색이 된다. 색상 변경이 중단되지는 않지만, 손으로 칠한 RGB 색이 그대로 유지되는 방식도 아니다.

기존 셰이더에는 별도의 아래 그림자 기능이 없다. 외곽선은 알파 경계에서 생성한다. 직접 그린 선을 그대로 쓰면서 이 기능도 켜 두면, 늘어난 알파 모양의 바깥에 추가 테마 외곽선이 생긴다.

배경 알파는 직접 그린 선과 음영에도 곱해진다. 기본 테마는 0.52, 마녀는 약 0.392이므로 자동 외곽선을 끄면 그려 둔 선도 함께 투명해진다. 특히 밝은 배경에서는 마녀의 직접 그린 선이 약해지는 모습을 확인할 수 있다. 자동 외곽선은 테마 테두리 알파를 따로 사용한다.

## 아래 음영과 알파

첨부본의 불투명 RGB 음영은 권장 조합에서 아래 변에 남고 색상 테마를 따라 어두워진다. 기존 분할선은 L7/B6/R3/T3이며, 테스트한 박스 크기 150×90, 280×110, 440×110 및 좌우 꼬리에서 눈에 띄는 연결 틈이나 꼬리 잘림은 관찰하지 못했다. 정확한 게임 내 화면 크기나 TMP 문장에 맞춘 ContentSizeFitter 검증은 별도다.

반면 음영의 알파를 낮추면 현재 셰이더가 그 부분을 내부로 인식하지 않을 수 있다. 내부 판정은 `textureAlpha × fillAlpha >= 0.341`이다. 마녀 테마는 `fillAlpha≈0.392`이므로 textureAlpha가 약 0.87보다 낮아지면 이 판정을 통과하지 못한다. 음영 알파를 128/255로 낮춘 진단에서는 아래 음영 부분에 테마 외곽선 색이 생기는 것을 실제 렌더로 확인했다. 이 디자인에서는 음영을 불투명 회색 RGB로 유지하는 편이 맞는다.

## 권장 조합의 적용 조건 — Suggested Later

1. PNG의 직접 그린 외곽선 53픽셀을 제외하고 기존 원본 알파 모양을 유지한다. 아래 음영 15픽셀은 불투명 RGB로 유지한다.
2. `SpeechBubblePrefab`의 `backgroundTextureInfluence`를 1로 설정하여 음영을 읽는다.
3. 기존 셰이더 외곽선과 캐릭터별 Border/Fill/Font Color 설정은 사용한다.
4. 현재 원본과 동일한 크기, 기존 `.meta`, 9분할 경계를 유지한다. 이후 실제 프리팹·씬에서 짧고 긴 문장, 폰트, 좌우 꼬리, 카메라 확대와 스프라이트 아틀라스를 확인한다.

이것은 권장 후속 범위이며 이번 조사에서 구현하지 않았다. 특히 프리팹 설정 변경은 별도 적용 작업에 해당한다. 직접 그린 어두운 선을 반드시 그대로 유지할 디자인이라면 자동 외곽선을 끄는 방식이나 채움·선·음영을 구분하는 마스크 설계를 선택해야 한다. 전자는 캐릭터별 테두리색 및 반투명 배경에서의 선 가독성 변화를 받아들이는 선택이다.

## 검증 범위와 재현 근거

- 모드: Investigation + 사용자가 요청한 시각 자료 제작. 게임 구현 변경은 없다.
- Unity 6000.4.2f1, Direct3D11, Linear 색 공간에서 검증용 C#를 컴파일하고 실제 UGUI Image 및 정확히 복사한 production 셰이더/머티리얼로 렌더했다.
- 원본과 첨부본은 Single Sprite, Point, 32 PPU, 기존 border/pivot으로 import했다. 테마는 현재 SpeechData 4종과 프리팹 기본값에서 읽었다.
- 색상 5종 × 방식 5종 × 배경 2종 = 50장, 마녀의 크기/반전 비교 24장, 음영 알파 비교 2장으로 총 76장이다.
- 5개 테마 모두에서 첨부 RGB를 흰색으로 바꾸어도 influence=0의 결과 픽셀이 같음을 비교했다. 영향값 1 및 자동 외곽선 ON/OFF의 차이도 픽셀 비교로 확인했다.
- `SpeechBubbleVisualReview.cs`는 이 폴더의 검증 전용 소스이며, `build-boards.ps1`은 native PNG에 표·설명을 붙이는 도구다. 생성형 이미지가 아닌 실제 셰이더 렌더다.
- 열린 게임 Editor/씬/실제 저장 슬롯은 조작하지 않았다. 검증용 UGUI는 격리 프로젝트에서만 만들어지고 정리된다.
- 전체 게임 프로젝트 compile, 실제 SpeechBubble MonoBehaviour lifecycle/TMP/ContentSizeFitter, URP/스프라이트 아틀라스/실제 카메라 조건의 완전한 일치, 전체 수동 Play Mode와 Player build는 검증하지 않았다. 따라서 이번 결과는 디자인/배경 셰이더 호환성에 관한 것이며 전체 게임 적용 완료 판정이 아니다.
- 기존 게임 관련 파일 19개의 작업 전후 SHA-256을 비교한다. `Assets`, `Packages`, `ProjectSettings`, 기존 `Docs`를 수정하지 않았다.
- Doc Impact Check: no doc update needed. SessionLogs/ErrorLog/DecisionLog 미갱신. 구조·문서 변경이 없어 Presentation HTML stale 후보 없음.
